# 몸 동작이 차를 움직이는 원리

> **이 문서는?** 체험자가 두 팔을 들면 차가 앞으로 가기까지 무슨 일이 일어나는지 단계별로 설명합니다.
> - **누가 읽나요?** 팀원 모두. 프로그래밍을 몰라도 읽을 수 있게 썼습니다. 발표나 부스에서 원리를 설명할 때도 씁니다.
> - **무엇이 있나요?** 0. 세 줄 요약 / 1. 전체 그림 / 2. 노트북 쪽 (1~6단계) / 3. 차 쪽 (7~8단계) / 4. 팔을 한 번 들면 일어나는 일 / 5. 바꿀 수 있는 설정 / 6. 이렇게 나눠 만든 덕분에 좋은 점 / 7. 낱말 풀이
> - **어느 코드 기준인가요?** 2026-11-11, 노트북 쪽은 `sunbell/motion` 브랜치의 `17bb5a0`, 차 쪽은 `yunsuk1590/arduino` 브랜치의 `fdc6850`입니다. 코드가 바뀌면 이 문서도 다시 봐야 합니다.
> - **작성**: 2026-11-11, 팀장 sunbell(Claude 도움). 위 두 브랜치의 코드를 직접 읽고 썼습니다. 「짐작」이라고 적은 것은 재 보거나 해 보지 않은 내용입니다.
> - **누가 고치나요?** 팀장 sunbell이 고칩니다.

## 0. 세 줄 요약

1. 노트북이 카메라 사진에서 몸의 점(코, 어깨, 손목 등)을 찾고, 「두 손목이 코보다 위인가」로 두 팔을 들었는지 판단합니다.
2. 그 상태가 0.25초 이어지면 진짜로 든 것으로 인정합니다. 인정되는 순간에 `F` 한 글자를 블루투스로 **딱 한 번** 보냅니다.
3. 아두이노는 `F`를 받으면 1초 동안 앞으로 가고 스스로 멈춥니다.

> **알아 둘 점**: 지금 설정에서는 **몸 동작으로 `S`를 보내지 않습니다.** 팔을 내려도 아무 글자도 가지 않고, 차는 1초 뒤 스스로 멈춥니다. `S`는 **프로그램을 끌 때 한 번만** 보냅니다(q 키나 창 닫기). 팔을 내릴 때 `S`를 보내게 하는 설정(`--letter-off S`)은 있지만, 지금은 꺼 두었습니다(아래 「5. 바꿀 수 있는 설정」).

## 1. 전체 그림

```
① 카메라 → ② 몸의 점 찾기 → ③ 동작 판단 → ④ 떨림 방지 → ⑤ 보낼 순간 찾기 → ⑥ 블루투스로 보내기
└──────────────────────── sunbell 노트북 (파이썬 프로그램) ────────────────────────┘
                                                        ↓ 「F」 한 글자
                                  ⑦ 아두이노가 글자 읽기 → ⑧ 바퀴 돌리고 1초 뒤 멈추기
                                  └──────────────── 차 (아두이노) ────────────────┘
```

- 노트북 쪽 코드는 `motion/` 폴더에 있습니다(`sunbell/motion` 브랜치, 팀 문서 PR #1에도 들어 있음). 몸 동작 인식 담당 sunbell이 만들었습니다.
- 차 쪽 코드는 `arduino/car/car.ino`입니다(`yunsuk1590/arduino` 브랜치). 아두이노 담당 yunsuk1590이 만들었습니다.
- 두 쪽은 **글자 하나**로만 이야기합니다. `F` = 앞으로, `S` = 멈춤입니다(11/8 sunbell 결정, [팀 결정 기록](team-decisions.md)).

## 2. 노트북 쪽 (1~6단계)

### 1단계 · 카메라가 사진을 계속 찍습니다
- 동영상은 사실 사진을 빠르게 넘기는 것입니다. sunbell 노트북 카메라는 1초에 약 30장을 찍습니다(11/11 시험에서 28.5장, 640×480 크기).
- 화면을 거울처럼 좌우로 뒤집어서, 화면의 왼쪽이 체험자의 왼쪽이 되게 합니다.
- 코드: `motion/camera.py`, `motion/run.py`

### 2단계 · 몸의 점을 찾습니다
- 구글이 만든 MediaPipe(미디어파이프)가 사진 한 장에서 코, 어깨, 팔꿈치, 손목 같은 관절 33곳의 위치를 찾아 줍니다.
- 점마다 화면 속 위치가 숫자(가로, 세로)로 나옵니다. 프로그램 화면에 보이는 뼈대 그림이 이 점들을 이은 것입니다.
- 사진 한 장에 약 0.02초(19~22 ms) 걸립니다. 지금은 처음 찾은 한 사람만 봅니다.
- 코드: `motion/pose.py`

### 3단계 · 점의 높이를 비교해서 동작인지 판단합니다
- 팔 하나마다 이렇게 봅니다(2026-10-04 sunbell 결정).
  - 손목이 잘 보이면 **손목이 코보다 위인지** 봅니다.
  - 손목이 화면 밖이거나 잘 안 보이면 **팔꿈치가 어깨보다 확실히 위인지** 봅니다.
- 두 팔이 모두 들렸으면 「두 팔 들기(`ARMS_UP`)」입니다.
- 이미 켜진 뒤에는 손목이 **어깨 아래로** 내려가야 꺼집니다. 켜는 기준과 끄는 기준을 다르게 두어서, 경계에서 켜졌다 꺼졌다 깜빡이지 않게 합니다.
- 이 판단은 사진 한 장마다 나옵니다. 이것을 「원래 결과(RAW)」라고 부릅니다.
- 몸 좌우 기울이기(`LEAN_LEFT`, `LEAN_RIGHT`)도 판단하지만, 지금은 글자를 보내지 않습니다.
- 코드: `motion/gestures/arms_up.py`, `motion/gestures/lean.py`

### 4단계 · 진짜 들었는지 잠깐 지켜봅니다 (떨림 방지)
- 사람이 가만히 있어도 점은 조금씩 흔들립니다. 그래서 판단이 한두 장 튈 수 있습니다.
- 그래서 두 팔 들기가 **0.25초 이어져야** 인정하고, **0.35초 동안 사라져야** 끕니다. 이렇게 인정된 결과를 「STABLE」이라고 부릅니다.
- 사람이 잠깐(0.5초보다 짧게) 안 잡히면 결과를 그대로 둡니다. 0.5초 넘게 안 보이면 모두 끕니다(11/5 sunbell 확정).
- 11/5 화면 시험에서 상태가 바뀐 횟수가 두 동작에서 22번·24번 → 6번·6번으로 줄었습니다.
- 대신 반응이 그만큼(0.25초) 늦어집니다. 덜 흔들리는 것과 빠른 것은 서로 맞바꾸는 관계입니다.
- 코드: `motion/stabilizer.py`

### 5단계 · 보낼 순간을 찾습니다: 「꺼짐 → 켜짐」인 순간에만
- 초인종처럼 생각하면 됩니다. 버튼을 꾹 누르고 있어도 「딩동」은 누르는 순간 한 번입니다.
- 팔을 계속 들고 있어도 `F`는 한 번만 갑니다. 한 번 더 보내려면 팔을 내렸다가(0.35초 넘게) 다시 들어야 합니다.
- 아래 두 경우에도 `F`가 나갑니다.
  - 프로그램을 켤 때 이미 팔을 들고 있었던 경우
  - 팔을 든 채로 0.5초 넘게 화면에서 사라졌다가 다시 잡힌 경우
- 코드: `motion/output.py`의 `LetterTrigger`

### 6단계 · 블루투스로 글자 하나를 보냅니다
- 노트북과 HC-06(차에 붙은 블루투스 부품)이 짝을 맺으면 노트북에 `COM11` 같은 「포트」가 생깁니다. 포트는 글자를 내보내는 출입구라고 보면 됩니다.
  - USB 선으로 이으면 `COM9`이고, 보내는 방법은 같습니다(sunbell 노트북 기준).
- 양쪽이 **같은 통신 빠르기(9600)** 로 약속해야 서로 알아듣습니다. 무전기의 채널과 말 빠르기를 맞추는 것과 비슷합니다.
- 안전장치가 있습니다.
  - 연결이 안 된 동안 생긴 `F`는 쌓아 두지 않고 **버립니다.** 쌓아 두면 연결되는 순간 아무도 팔을 안 들었는데 차가 출발할 수 있기 때문입니다.
  - 연결이 끊기면 3초마다 다시 연결합니다. 프로그램은 꺼지지 않습니다.
  - 보내는 일은 따로 돌아가서, 블루투스가 느리게 열려도 화면은 멈추지 않습니다.
- 포트가 열렸다고 글자가 차까지 도착했다는 뜻은 아닙니다. 도착은 차 시험으로 확인했습니다(11/11, 바닥에서 5번 중 5번).
- 코드: `motion/output.py`의 `SerialLink`

## 3. 차 쪽 (7~8단계)

코드는 모두 `arduino/car/car.ino` 하나에 있습니다.

### 7단계 · 아두이노가 들어온 글자를 확인합니다
- HC-06이 무선으로 받은 글자를 선으로 아두이노에 넘깁니다.
- 아두이노는 같은 일을 쉬지 않고 되풀이합니다(`loop`). 「블루투스로 들어온 글자 있나? USB 선으로 들어온 글자 있나?」를 계속 확인합니다. 어느 쪽으로 들어온 글자든 똑같이 처리합니다.
- 글자 표는 이렇습니다.

| 글자 | 하는 일 |
|---|---|
| `F` | 앞으로 갑니다(정해진 시간 뒤 스스로 멈춤) |
| `S` | 바로 멈춥니다 |
| 그 밖의 글자, 줄바꿈 | 무시합니다 |

### 8단계 · 바퀴를 돌리고, 1초 뒤 스스로 멈춥니다
- `F`가 오면 모터 쉴드의 왼쪽(M1)과 오른쪽(M4) 모터를 세기 255(가장 셈)로 앞으로 돌리고, **출발한 시각을 적어 둡니다.**
- 시계를 보다가 1초가 지나면 스스로 멈춥니다.
- 가는 도중 `F`가 또 오면 그때부터 1초를 **다시 잽니다.** 그래서 동작을 이어서 하면 차가 더 멀리 갑니다.
- 기다리는 동안 멈춰 있지 않고 시계만 보기 때문에, 가는 도중에 온 `S`도 바로 받아서 멈출 수 있습니다.
- 정한 값: 가는 시간 1초, 가는 도중 `F`는 시간 다시 잼(11/10, sunbell 제안·yunsuk1590 동의), 모터 세기 255(11/11 sunbell). → [팀 결정 기록](team-decisions.md)

## 4. 팔을 한 번 들면 일어나는 일 (시간 순서)

| 언제 | 일어나는 일 |
|---|---|
| 0초 | 체험자가 두 팔을 듭니다 |
| 약 0.25초 | 떨림 방지를 통과합니다 → `F`를 보냅니다 |
| 곧바로 | 차가 출발합니다. 팔을 들고 출발까지는 대략 0.3초로 짐작합니다(블루투스로 글자가 가는 시간은 재지 않았습니다) |
| 출발 후 1초 | 차가 스스로 멈춥니다 |

차가 스스로 멈추기 때문에, 노트북 프로그램이 꺼지거나 블루투스가 끊겨도 차가 계속 달려 나가지 않습니다.

## 5. 바꿀 수 있는 설정

노트북 프로그램을 실행할 때 명령 뒤에 붙여서 바꿉니다. 예: `run.bat --port COM11`

| 설정 | 하는 일 | 지금 값 |
|---|---|---|
| `--port` | 글자를 보낼 포트. 적지 않으면 글자를 보내지 않고 화면과 터미널에만 표시합니다(가짜 보내기) | 없음(발표회는 `COM11`, 예비 `COM9`) |
| `--send-on` | 어떤 동작이 켜질 때 보낼지(`ARMS_UP`, `LEAN_LEFT`, `LEAN_RIGHT`) | `ARMS_UP` |
| `--letter-on` | 동작이 켜지는 순간 보낼 글자 | `F` |
| `--letter-off` | 동작이 꺼지는 순간 보낼 글자. 빈칸이면 보내지 않습니다 | 빈칸 |
| `--letter-quit` | 프로그램을 끌 때 한 번 보낼 글자 | `S` |

- 지금은 동작 하나에 글자 하나만 보낼 수 있습니다. 동작마다 다른 글자를 보내려면 프로그램을 고쳐야 합니다(「운영 8 · 콘텐츠별 동작」에서 동작이 정해진 뒤).

## 6. 이렇게 나눠 만든 덕분에 좋은 점

- **「글자 약속」만 맞으면 두 쪽을 따로 만들 수 있습니다.** 노트북 쪽은 sunbell, 차 쪽은 yunsuk1590이 각자 만들었고, 11/11에 처음 이어 보았는데 바로 통과했습니다.
- **각자 따로 시험할 수 있습니다.**
  - 차: 아두이노 프로그램의 시리얼 모니터에서 키보드로 `F`를 쳐서 시험합니다.
  - 노트북: `--port` 없이 실행하면 글자를 화면에만 표시합니다(가짜 보내기).
- **새 동작을 더하기 쉽습니다.** `motion/gestures/` 폴더에 판단 파일 하나를 추가하면 4~8단계를 그대로 탑니다(방법은 `motion/README.md`의 「9. 새 동작 추가하는 방법」). 장애물 장치(「개발 10 · 장애물 제어」)도 같은 방식으로 글자를 받게 만들 수 있습니다. 이것은 구조를 보고 한 말이고, 아직 해 보지는 않았습니다.

## 7. 낱말 풀이

| 말 | 뜻 |
|---|---|
| MediaPipe(미디어파이프) | 구글이 만든 도구입니다. 카메라 사진에서 사람 몸의 관절 위치를 찾아 줍니다 |
| RAW / STABLE | 떨림 방지 전의 원래 결과 / 떨림 방지를 거쳐 인정된 결과 |
| 떨림 방지 | 결과가 일정 시간 이어져야 바뀌게 해서, 한순간 튀는 판단을 막는 것 |
| 포트(COM) | 노트북이 글자를 내보내는 출입구. 블루투스나 USB 선을 이으면 `COM11`, `COM9`처럼 번호가 생깁니다 |
| 9600 | 노트북, HC-06, 아두이노가 맞춘 통신 빠르기(1초에 보내는 신호 수) |
| HC-06 | 아두이노에 붙이는 블루투스 부품. 노트북과 무선으로 글자를 주고받습니다 |
| 아두이노 | 작은 컴퓨터 보드. 프로그램을 올려서 모터를 움직입니다. RC카 키트의 두뇌입니다 |
| 모터 쉴드 | 아두이노 위에 꽂아 바퀴 모터를 돌리는 판 |
| 시리얼 모니터 | 아두이노 프로그램 안의 창. 키보드로 글자를 보내거나, 아두이노가 찍은 글을 볼 수 있습니다 |
