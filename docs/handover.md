**하지 말 것** (모두 실제로 문제가 있었거나, 있다고 확인된 것)
- mediapipe를 **1.0.1로 올리지 않습니다.** 1.0.1은 맥에서 몸 인식을 시작하자마자 강제 종료됩니다(공식 이슈 google-ai-edge/mediapipe#6356).
- `opencv-python`을 **함께 설치하지 않습니다.** 지금 쓰는 `opencv-contrib-python`과 충돌합니다.
- `requirements.txt`에 **한글을 쓰지 않습니다.** 한국어 윈도우의 설치 도구(pip)가 한글을 읽다가 멈춥니다.
- 레포 맨 위의 `requirement.txt`(끝에 s가 없음)와 **헷갈리지 않습니다.** 그 파일은 원래 있던 프로그램(`Main.py`, mediapipe 0.10.14)용이고, `motion/`은 쓰지 않습니다.
- 부품 버전을 바꾸면 팀원 모두가 setup을 다시 해야 합니다. 바꾸기 전에 팀과 상의하고 `decisions.md`에 적습니다.

**설치가 맞게 됐는지 확인하는 법**: setup이 끝날 때 아래처럼 나오면 이 문서와 같은 환경입니다.

```
  mediapipe 1.0.0 / opencv 5.0.0 / numpy 2.4.6
  mediapipe 1.0.0 / PoseLandmarker OK

[완료] 준비가 끝났습니다. 이제 run 파일을 더블클릭해서 실행하세요.
```

## 2. 처음 시작하기 (순서대로)

**① 파이썬 3.11.9와 git 설치**: 위 1번 표를 따릅니다. git 받는 곳은 [`motion/README.md`](../motion/README.md) 1번에 있습니다.

**② git에 내 이름 알려 주기** (컴퓨터마다 처음 한 번)
터미널(윈도우는 PowerShell)에서 입력합니다. 커밋에 이 이름이 작성자로 남습니다.

```
git config --global user.name "내 깃허브 아이디"
git config --global user.email "깃허브에 등록한 이메일"
```

**③ 레포 받기 + 내 브랜치 만들기**
브랜치는 레포 안의 내 작업 공간입니다. `내아이디` 자리에 본인 깃허브 아이디를 영어로 넣습니다.

```
git clone https://github.com/yunsuk1590/Sunjong_please.git
cd Sunjong_please
git switch sunbell/motion
git switch -c 내아이디/motion
git push -u origin 내아이디/motion
```

- 맥 시험 때문에 레포를 **이미 받아 두었다면**, 첫 줄 대신 `Sunjong_please` 폴더에서 `git fetch`를 하고 셋째 줄부터 합니다. 셋째 줄 다음에 `git pull`을 한 번 더 합니다.
- **push가 거절되면** 레포 주인 yunsuk1590 님에게 GitHub 레포 설정의 Collaborator(함께 올릴 수 있는 사람)로 추가해 달라고 합니다.
- 맥에서 push할 때 비밀번호를 물으면, 깃허브 비밀번호가 아니라 **토큰(Personal access token)**을 넣어야 합니다. 만드는 법: <https://docs.github.com/ko/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens>

**④ 설치**: `motion` 폴더의 `setup.bat`(윈도우) 또는 `setup.command`(맥)를 더블클릭합니다. 처음에는 몇 분 걸립니다. 위 1번의 `[완료]` 화면이 나오면 성공입니다.

**⑤ 실행**: `run.bat` 또는 `run.command`를 더블클릭합니다.
- 내 몸 위에 뼈대가 그려지고, 화면 아래에 큰 글씨(`NONE`, `ARMS_UP` 등)가 나오면 성공입니다.
- 맥에서 처음 실행할 때 카메라 접근을 물으면 **허용**합니다.
- 끄기: 창에서 `q` 또는 `Esc`를 누릅니다. 끄면 터미널에 요약이 찍힙니다.
- 화면 읽는 법과 문제 해결은 [`motion/README.md`](../motion/README.md) 5번과 7번에 있습니다.

**⑥ 작업을 올리기**

```
git add 바꾼파일
git commit -m "motion - 무엇을 바꿨는지"
git push
```

- 커밋 메시지 형식: 코드는 `motion - …`, 문서는 `문서 - …`로 시작합니다(지금까지의 관례).

## 4. 마지막으로 하던 것: 4단계 떨림 방지

### 무엇을 만들었나
- `motion/stabilizer.py`는 MediaPipe 결과가 사진 한두 장에서만 튀어도 화면 결과가 바뀌지 않게 합니다.
  - 결과가 정해진 시간 동안 이어져야 바뀝니다. 켜질 때와 꺼질 때의 기다리는 시간이 따로 있습니다.
  - 사람이 짧게 안 보이면 결과를 그대로 둡니다. 0.5초(`lost`) 넘게 안 보이면 모든 동작을 끕니다.
- 화면 구성
  - `RAW:` 줄: 떨림을 막기 전 원래 결과
  - 아래 큰 글씨: 떨림을 막은 결과(STABLE)
  - 큰 글씨 위의 색 띠: 최근 3초 동안의 RAW(위)와 STABLE(아래)
  - `WAIT` 줄: 지금 쓰는 기다리는 시간
- 끌 때 요약 맨 아래에 `원래 결과(RAW) n번 바뀜 → 떨림 방지 후(STABLE) m번`이 찍힙니다.
- Claude가 시간에 따라 바뀌는 가짜 판정 12가지로 시험해 통과했습니다. 그 시험 코드는 레포에 없습니다.

### 화면 확인 방법과 결과 (10/8 sunbell, 윈도우 노트북)

| 해 볼 것 (2 m쯤 떨어져서) | 성공이면 | 10/8 결과 |
|---|---|---|
| 1. 막대의 점이 노란 선(22도) 근처에 오게 **애매하게 기울인 채 버티기** | RAW는 깜빡여도 큰 글씨는 깜빡이지 않음 | ✓ 세 설정 모두 안정 |
| 2. 두 팔을 **아주 빠르게** 들었다 내리기 | 큰 글씨가 안 켜지거나 잠깐만 켜짐 | "더 안정적으로"가 설명대로 가장 잘 느껴짐 |
| 3. 두 팔을 **들고 있기** | 큰 글씨가 RAW보다 살짝 늦게 켜짐. **굼뜨게 느껴지면 안 됨** | "더 안정적으로"가 가장 잘 느껴짐. **굼떴는지는 아직 답 없음** |
| 4. 화면 **밖으로 나가기** | 1초 안에 큰 글씨가 `NONE` | ✗ **`NONE`이 뜨지 않음.** 배경에 물건이 많아서일 수 있다고 짐작했고, 원인은 확인 전 |
| 5. `q`로 끄기 | 요약 맨 아래에서 m이 n보다 작음 | 확인 못 함 |

비교한 세 가지 기다리는 시간(초, 켜짐/꺼짐)

| | 더 빠르게 | 지금 기본값(시작값) | 더 안정적으로 |
|---|---|---|---|
| 두 팔 들기 | 0.10 / 0.15 | 0.15 / 0.25 | 0.25 / 0.35 |
| 기울이기 | 0.05 / 0.10 | 0.10 / 0.15 | 0.20 / 0.25 |

### 남은 일 (순서대로)

**A. 기다리는 시간 정하기** (미정)
- 남은 질문은 "더 안정적으로"에서 3번을 할 때 굼뜨게 느껴지는가 하나입니다.
- Claude 의견: 굼뜨지 않으면 "더 안정적으로", 조금이라도 굼뜨면 "지금 기본값"을 추천합니다.
- 알아 둘 점: "더 안정적으로"는 두 팔을 내린 뒤에도 0.35초 동안 `ARMS_UP`이 유지됩니다. 자동차로 치면 "팔을 내렸는데 0.35초 더 간다"는 뜻입니다. 그래서 두 번째 목표(값으로 내보내기)를 정할 때 다시 봅니다.
- 정하면 고칠 곳
  - `motion/config.py`의 `DEFAULTS`: `arms_on`, `arms_off`, `lean_on`, `lean_off`
  - [`gesture-rules.md`](gesture-rules.md)의 「깜빡임 막기 ② 시간」 줄: 숫자를 고치고 "시작값"을 "확정"으로
  - [`decisions.md`](decisions.md): 결정 한 줄을 더하고, 맨 아래 「다음 단계에서 정할 것」의 4단계 줄을 지움
  - [`motion/README.md`](../motion/README.md) 5번 화면 예시의 `WAIT` 줄과 6번 표의 기본값

"더 안정적으로"로 시험하는 명령(`motion` 폴더에서)
- 윈도우 PowerShell: `.\run.bat --arms-on 0.25 --arms-off 0.35 --lean-on 0.2 --lean-off 0.25`
- 맥 터미널: `./run.command --arms-on 0.25 --arms-off 0.35 --lean-on 0.2 --lean-off 0.25`

**B. 4번 문제: 화면 밖으로 나가도 `NONE`이 안 뜸** (원인 미확인)
다시 해 보면서 아래 네 가지를 봅니다. 화면을 캡처해 두면 좋습니다.
1. 나갔을 때 큰 글씨에 무엇이 남았나? (`ARMS_UP`, `LEAN_LEFT` 등. 아니면 이미 `NONE`인데 뼈대만 남았나?)
2. 왼쪽 위 둘째 줄 끝이 `PERSON 1`인가, `NO PERSON`인가?
3. 화면 속 물건(의자, 걸린 옷 등) 위에 뼈대가 그려졌나?
4. 몸이 완전히 화면 밖으로 나갔나? 손이나 어깨가 가장자리에 걸려 있으면 사람으로 잡히는 것이 정상입니다.

원인에 따라 고칠 방향이 다릅니다. 아래는 **후보일 뿐이고 아무것도 정하지 않았습니다.**
- 물건을 사람으로 잡는 경우
  - 사람이라고 인정하는 확신 기준 높이기(`motion/pose.py`의 `CONFIDENCE = 0.5`)
  - 어깨가 잘 보일 때만 사람으로 치기
  - 화면에서 "체험 구역"만 잘라서 보기
- 몸 일부가 걸려 있던 경우: 고칠 것이 없습니다.

**C. 5번 확인**: `q`로 끈 뒤 요약 맨 아래 두 줄(`ARMS_UP: … → …`, `LEAN: … → …`)에서 m이 n보다 작은지 봅니다.

**D. 마무리**: A~C가 끝나면 [`plan-motion-recognition.md`](plan-motion-recognition.md) 진행 표의 4단계를 "완료"로 바꾸고 커밋합니다.

## 7. 지금까지 지켜 온 작업 규칙

- **main에 직접 올리지 않습니다.** 본인 브랜치에서 작업합니다. `sunbell/motion`에도 직접 올리지 않습니다(sunbell이 돌아와서 합칩니다).
- **다른 팀원의 파일은 수정하거나 지우지 않습니다.**
  - 레포 맨 위의 `Main.py`, `Handcontroller.py`, `VirtualGameController.py`, `requirement.txt`, `README.markdown`, `.vscode/`가 여기에 해당합니다.
  - 새 코드는 `motion/`에, 문서는 `docs/`에 둡니다.
- 무언가를 정하면 [`decisions.md`](decisions.md)에 날짜·내용·이유·**정한 사람**을 적습니다.
- 팀과 함께 정할 것은 정하지 말고 [`team-agenda.md`](team-agenda.md)에 올립니다(구현·개발 쪽 / 운영 쪽).
- 직접 화면으로 확인한 것과 짐작이나 계산으로 예상한 것을 구분해서 적습니다. AI(Claude 등)에게 받은 분석에는 「Claude 분석」처럼 표시합니다.
- AI 도구로 이어서 작업한다면, 먼저 이 문서와 `docs/` 폴더의 문서를 읽게 하세요. 정해진 것과 아직 안 정한 것을 구분하게 하고, 안 정한 것을 AI가 마음대로 정하지 않게 합니다.

## 9. sunbell이 돌아왔을 때 (메모)

팀원 브랜치의 작업을 내 브랜치로 가져옵니다. `팀원아이디` 자리에 팀원 브랜치 이름을 넣습니다.

```
git fetch
git switch sunbell/motion
git merge origin/팀원아이디/motion
```

- 그사이 `sunbell/motion`에 새 커밋이 없었다면, 팀원 작업이 그대로 이어 붙습니다(충돌 없음).
- 그 뒤 push하기 전에 무엇이 바뀌었는지 함께 확인합니다.
