# 원본과 수정본 분석 (2026-09-29)

MediaPipe 담당(sunbell)이 새 동작 인식 코드를 쓰기 전에, 기존 코드 두 개를 코드 수정 없이 분석한 결과입니다.

- **원본**: 지인(vividhyeok)의 손동작 게임 컨트롤러 — <https://github.com/vividhyeok/Vgc-Controler>
- **수정본**: 우리 팀 레포 main 브랜치에 올라간 버전(2026-09-19, yunsuk1590)
- **원본의 원본**: 원본도 2022년 다른 사람(Gokul9404)의 코드를 가져와 고친 것입니다 — <https://github.com/Gokul9404/Virtual-Game-Controller>

## 한 줄 요약

원본과 수정본은 **손가락으로 PC 게임 키보드를 누르는 프로그램**입니다. 동작을 알아보는 부분은 둘이 똑같고, 수정본은 원본이 윈도우에서 잘 켜지도록 세 곳(카메라 여는 방식, 음성, 창 크기)을 고친 것입니다. 옛 MediaPipe 방식을 쓰고 라이선스가 없어서, 우리 몸 동작 인식 코드는 **참고만 하고 새로 작성**하기로 했습니다(`docs/decisions.md`).

## 1. 원본

### 구성

| 파일 | 하는 일 | 길이 |
|---|---|---|
| `Main.py` | 프로그램 창(PyQt5): 카메라 영상, 시작/정지 버튼, 키 설정 창. **이 파일을 실행하면 시작** | 585줄 |
| `VirtualGameController.py` | 카메라 열기 → 손동작 판정 → 키보드 누르기(pydirectinput), 마우스 모드, 윈도우 음성 안내 | 412줄 |
| `Handcontroller.py` | MediaPipe로 손 관절 21개 점(랜드마크) 찾기, 손가락이 펴졌는지 판단 | 74줄 |

- 창이 0.03초마다 카메라 사진 한 장을 가져와서 손 찾기 → 동작 판정 → 키 누르기 → 화면 그리기를 **한 줄로 차례대로** 합니다.

### MediaPipe 기능과 버전

- 손 인식(Hands), 한 손만, 버전 0.10.14(2024년 5월).
- **옛 방식(legacy Solutions, `mp.solutions.hands`)**으로 불러 씁니다.

### 손동작을 구분하는 방식

- 인공지능은 "관절 점 찾기"까지만 합니다. 어떤 동작인지는 사람이 짠 **규칙(if문)**이 정합니다.
- 손가락 끝 점이 관절 점보다 위에 있으면 "폈다"고 봅니다. 그리고 손가락 끝이 **화면에 그려진 빨간 상자 안에 있을 때만** 동작으로 인정합니다.
- 주먹 → 점프 / 검지 → 위 / 검지와 중지 → 아래 / 엄지 → 왼쪽 / 새끼손가락 → 오른쪽
- 설명서(README)와 실제 동작이 일부 다르고, 작성자가 README에 "이 부분 잘못됐음 추후 고치겠음"이라고 적어 두었습니다.

### 계보

| 시기 | 누가 | 무엇을 |
|---|---|---|
| 2022~2023 | Gokul9404 | OpenCV 창 하나짜리 손동작 게임 컨트롤러 |
| 2025-05-14 | vividhyeok(지인) | 포크(통째로 복사)해서 PyQt5 창, 게임용 키 입력(pydirectinput), 한국어 주석을 붙이고 크게 고침 |

지인이 고치면서 **정확도가 떨어질 수 있는 곳이 2곳** 생겼습니다.
1. 2022년 코드는 실제 카메라 크기로 좌표를 계산했는데, 지인 버전은 960×720으로 고정해서 계산합니다. 카메라가 이 크기를 지원하지 않으면 화면의 빨간 상자와 실제 판정 위치가 어긋납니다.
2. 엄지 판정에서 왼손/오른손 구분이 빠졌습니다.

### 라이선스

- 원본과 원본의 원본 **모두 라이선스가 없습니다**(라이선스 파일도, 문구도, 저장 기록 전체에도 없음. GitHub도 "license: 없음"으로 표시).
- 라이선스가 없으면 저작권자가 모든 권리를 가진 상태입니다. 보고 참고하는 것은 괜찮지만, 복사·수정·배포는 원칙적으로 허락이 필요합니다.
- 우리 팀 레포는 **공개 상태**이고 이 코드를 그대로 담고 있습니다 → 팀에서 확인이 필요합니다(아래 질문 5번).
- MediaPipe 자체는 자유롭게 써도 되는 라이선스(Apache 2.0)입니다.

### 달라진 점

| 바뀐 곳 | 실제로 달라지는 점 | 코드에 적힌 이유 |
|---|---|---|
| 카메라 여는 방식(`cv2.CAP_DSHOW`) | 카메라가 빨리 켜질 수 있음 | "윈도우 카메라 충돌 방지" |
| 음성 안내 끄기 | 목소리가 안 나옴 | "멈춤을 유발할 수 있으므로" |
| 창 크기 1600×1400 → 1200×900, 영상 1280×960 → 960×720 | 창이 작아짐 | 없음 |
| 터미널에 `[시스템] 1.~5.` 진행 상황 출력 | 어디까지 켜졌는지 보임 | 없음 |
| `.gitignore` 정리(원본에 실수로 들어간 실행 명령 3줄 삭제, `Vgc-Controler/` 제외 추가) | 없음 | 없음 |
| `.vscode/settings.json` 한 줄 추가 | 없음 | 없음 |

- 카메라 방식 참고: 윈도우 기본 방식(MSMF)은 카메라를 여는 데 20초에서 몇 분까지 걸린 사례가 보고되어 있고, DSHOW 방식으로는 바로 열렸다는 보고가 있습니다(OpenCV 이슈 #17687).
- **손 인식과 동작 판정 부분은 하나도 바뀌지 않았습니다.** 수정본은 "원본이 윈도우에서 잘 켜지게 만든 응급 처치"이고, 인식 자체를 개선한 것은 아닙니다.

### 새 코드로 가져가는 것

| 수정본의 변경 | 새 코드에서 |
|---|---|
| 카메라 `CAP_DSHOW` | 기본값으로 가져감(실제로 재 보고 확정) |

## 3. 우리 목표 기준 종합 평가

원본과 수정본은 인식 부분이 같아서 한 번에 평가했습니다.

| 기준 | 평가 | 이유 |
|---|---|---|
| 몸 동작 인식으로 넓히기 쉬운가 | 어려움 | 손 찾기, 판정, 키 누르기, 그리기가 한 덩어리로 섞여 있음. 결과가 "위·아래·좌·우·점프" 5칸에 고정됨 |
| 딜레이를 늦추는 부분 | 의심되는 곳 4곳 | ① 모든 처리를 창 하나에서 차례로 함 → 한 장이 늦으면 전부 밀림 ② 카메라가 쌓아 둔 옛날 사진을 읽을 수 있음 ③ 960×720 요청 — 카메라에 따라 초당 장수가 떨어짐 ④ 매번 영상을 큰 화면으로 확대해서 그림 |
| 떨림 방지, 사람 없을 때 처리 | 없음 | 매 장의 결과를 그대로 씀. 손이 화면에서 사라지면 눌려 있던 키가 떼어지지 않음 |
| MediaPipe 방식 | 낡음 | 옛 방식은 2023년 3월 공식 지원 종료, **2025년 12월(0.10.30)부터 최신 설치 파일에서 빠짐**. 원본은 0.10.21 이하에서만 돌아가고, 0.10.14는 파이썬 3.12까지만 지원. 옛 방식의 몸 인식은 한 번에 한 명만 가능 |
| 팀원 3명이 이해·수정하기 쉬운가 | 보통 이하 | 한국어 주석은 좋음. 하지만 1,000여 줄 대부분이 PC 게임 키 설정과 마우스용. 윈도우 전용 부품(pywin32, pydirectinput)이라 맥에서 안 돌아감. 설치 목록에 PyQt5와 pydirectinput가 빠져 있음 |
| 손 인식이 필요한가 | 아마 불필요 | 몸으로 자동차를 조작한다면 포즈(몸 관절 33개 점) 인식이 중심. 포즈에도 손목과 손끝의 대략적인 위치가 있음. 몸 전체가 보이게 멀리 서면 손이 작게 찍혀 손 인식이 불안정해지기 쉬움 |

## 4. MediaPipe 현황 (2026-09-29 조사)

- 최신 버전: 1.0.1(2026-08-14). 공식 문서 기준 파이썬 3.9 이상.
  - 10/4 추가 확인: 1.0.1은 맥에서 몸 인식이 강제 종료되는 버그가 있습니다(이슈 #6356). 그래서 우리는 1.0.0을 씁니다.
  - 0.10.30 이후 MediaPipe의 맥용 설치 파일은 Apple 칩(M1 이후)용뿐이라, 인텔 맥에는 설치되지 않습니다.
- 옛 방식(`mp.solutions`)은 0.10.30부터 삭제되었습니다. 구글 담당자: "MediaPipe Solutions 지원을 없앴으니 MediaPipe Tasks로 옮기라"(GitHub 이슈 #6192).
- 권장 방식: MediaPipe Tasks의 `PoseLandmarker`. 한 사람당 몸 관절 33개 점을 줍니다. `num_poses`로 여러 명도 가능하지만 여러 명일 때 정확도는 공식 보장이 없고, 사람마다 이름표(ID)가 붙지 않습니다.
- 윈도우 웹캠: `CAP_PROP_BUFFERSIZE`(쌓아 둘 사진 수 설정)는 윈도우에서 효과가 없을 가능성이 큽니다. 그래서 새 코드는 "가장 최근 사진 1장만 들고 있는" 방식으로 카메라를 읽습니다.
