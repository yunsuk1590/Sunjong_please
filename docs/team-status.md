## 0. 지금 가장 급한 일: 11/11 학과 발표회 시연

**11월 11일(수)** 우리 학과 일정으로 **자체 최종발표회**가 있습니다. 이때 **몸 동작 인식으로 차가 움직이는 모습**을 보여 줘야 합니다. **오늘(11/11)입니다.**

시연 흐름은 이렇게 하기로 했습니다(11/5 sunbell 결정, [팀 결정 기록](team-decisions.md)의 「11/11 학과 발표회 시연」).

```
웹캠 → [몸 동작 인식] → [글자 하나 보내기] → (HC-06 블루투스) → [아두이노: 글자를 받아 움직이기] → 차
       └──── sunbell 윈도우 노트북 ────┘                        └──── yunsuk1590이 새로 쓰는 코드 ────┘
```

- **정해진 것**: 보여 줄 것은 **차**(차단봉은 하지 않음) / sunbell 윈도우 노트북 + HC-06 블루투스, 예비로 USB 선 / 아두이노 코드는 yunsuk1590이 새로 씀
- **11/8에 더 정해진 것**(sunbell): 「보낼 글자 약속」은 `F` = 앞으로, `S` = 멈춤입니다. 차는 `F`를 받으면 정해진 시간만 앞으로 가고 스스로 멈춥니다. 아두이노 코드는 블루투스와 USB 선 양쪽에서 같은 글자를 받습니다.
- **11/10 현황**: 노트북 쪽 글자 보내기(`sunbell/motion`)와 차를 움직이는 아두이노 코드(`yunsuk1590/arduino`)가 모두 깃허브에 올라왔습니다. 아직 차와 이어 보는 시험은 하지 않았습니다. 11/10 sunbell이 발표회 차에는 yunsuk1590의 코드를 먼저 올려 시험하고, 안 되면 sunbell 예비 코드(`sunbell/arduino`)를 쓰기로 정했습니다.
- **11/11 현황**: 두 사람 모두 담당자 코드를 자기 차에 올려 시험했습니다. sunbell 노트북에서 블루투스로 보낸 글자로 차가 움직이는 것까지 확인했습니다. 가는 시간 1초, 가는 도중 `F`는 시간 다시 잼, 모터 세기 255로 정했습니다([팀 결정 기록](team-decisions.md)).
  - 몸 동작 프로그램으로 차를 움직이는 시험도 통과했습니다(sunbell 노트북과 sunbell 차, 블루투스 `COM11`). 바닥에서 동작을 5번 해서 차가 5번 모두 움직였고, 리허설 146초 동안 뒤로 사람이 지나가도 잘못 켜진 적이 없었습니다.
- **아직 정할 것·할 것**: 어떤 몸 동작으로 움직일지, USB 선 예비책을 몸 동작 프로그램으로 한 번 시험하기(발표 전, 11/11 sunbell 결정. 11/11 04:10 기준 아직 안 함), 노트북 전원을 꽂은 상태와 실제 발표장 확인 → 안건 「운영 7 · 11/11 발표회 시연」
- **발표회 뒤 (이음제 11/28 준비)**: 이음제 콘텐츠는 2개로 따로 합니다(11/11 sunbell, 아래 「1. 기본 정보」). 발표회가 끝나면 바로 동작 다양화 회의(「운영 8 · 콘텐츠별 동작」)와 장애물 부품 조사(「개발 10 · 장애물 제어」)를 시작합니다.
- **새로 만들어야 하는 곳 두 군데** (둘 다 깃허브에 올라왔고, 11/11 이어 보는 시험을 통과했습니다)
  1. 몸 동작 인식이 동작을 알아보면 **글자 하나를 블루투스로 보내는 부분** (sunbell 노트북 쪽)
  2. 그 글자를 받아 **차를 움직이는 아두이노 코드** (yunsuk1590, [아두이노 담당 작업 안내](arduino-brief.md)의 「첫 할 일 ②」)

## 2. 파트별 상태

### 몸 동작 인식 (MediaPipe)
**담당**: sunbell · **마지막 확인**: 11/11 (`sunbell/motion` 브랜치의 커밋 `17bb5a0` 기준)

- **하는 일**: 웹캠 영상에서 체험자의 몸 동작(예: 두 팔 들기, 몸 기울이기)을 알아봅니다.
- **지금**: 「첫 번째 목표」(동작을 제대로 알아보는지 화면으로 확인하기)의 5단계 중 **1~4단계가 끝났습니다**(4단계는 11/5에 마침).
  - 4단계는 「떨림 방지」입니다. 인식 결과가 한순간 튀어도 화면의 결과가 흔들리지 않게 합니다. 11/5 sunbell 화면 확인에서 굼뜨지 않았고, 화면 밖으로 나가면 「동작 없음」이 제대로 떴습니다. 부스 리허설 때 다시 확인합니다.
  - 11/8에 11/11 발표회용 **글자 보내기**를 만들었습니다(`71945ff`). 동작을 알아보면 `F`를 COM 포트로 보냅니다. 자동 시험을 함께 만들었습니다.
  - 11/11 sunbell 차로 블루투스(`COM11`) 시험을 통과했습니다(`17bb5a0`). 동작을 할 때마다 `F`를 한 번 보내 차가 1초 가고 멈췄고, 프로그램을 끄면 `S`를 보냈습니다. 바닥 시험 5번 모두 움직였고 버린 글자는 없었습니다(28.5 fps). 리허설 146초 동안 잘못 켜진 적이 없었습니다(29.6 fps). 시험은 지금 프로그램이 알아보는 「두 팔 들기」로 했고, 어떤 동작으로 할지는 아직 안건입니다.
  - USB 선 예비책(`--port COM9`)은 몸 동작 프로그램으로 아직 해 보지 않았습니다. 발표 전에 한 번 해 보기로 했습니다(11/11 sunbell).
- **다음**: 원래 순서는 5단계(속도 다듬기) → 첫 번째 목표 완료 → 「두 번째 목표」(알아본 결과를 다른 프로그램이 받을 수 있는 값으로 내보내기)입니다.
  - 11/8에 sunbell이 11/11 발표회를 위해, 알아본 결과를 **글자 하나로 블루투스에 보내는 부분**을 바로 시작하기로 했습니다.
- **걸리는 것**: 맥에서는 아직 한 번도 실행해 보지 않았습니다. → 안건 「개발 6 · 팀원 컴퓨터」 (발표회는 sunbell 윈도우 노트북으로 하므로 발표회에는 영향이 없습니다.)
- 자세히: [몸 동작 인식 계획서](plan-motion-recognition.md)

### 아두이노
**담당**: yunsuk1590 · **마지막 확인**: 11/11 (`yunsuk1590/arduino` 브랜치의 커밋 `fdc6850` 기준)

- **하는 일**: 노트북이 보낸 명령을 받아 차(그리고 만들기로 정하면 차단봉)를 움직이는 아두이노 프로그램과 배선.
- **지금**: 키트 조립과 시험(앞뒤 이동, 스마트폰 앱 조종)은 끝났습니다. 11/10에 글자를 받아 차를 움직이는 코드(`arduino/car/car.ino`)와 작업 기록(`arduino/README.md`)을 올렸습니다.
  - 11/8 약속을 모두 따르고, sunbell 노트북에서 컴파일됐습니다(11/10 sunbell 확인).
  - 11/11 yunsuk1590 차에 올려 USB 시험을 했고 정상이었습니다(세기 200). 블루투스는 yunsuk1590 차로는 시험 전입니다.
  - 11/11 sunbell 차에도 같은 코드(`aa7ae28`)를 올려 시험했습니다. 블루투스로도 동작했고, 바닥에서는 세기 255가 필요했습니다. 지금 sunbell 차 보드에는 세기만 255로 바꾼 판이 올라가 있습니다.
  - 11/11 yunsuk1590이 `car.ino`의 모터 세기를 255로 바꿔 올렸습니다(`fdc6850`). 자기 차에서 USB로 바닥 시험을 했고 잘 작동했습니다. sunbell 노트북에서도 컴파일 오류가 없었고, sunbell 차 보드와 값이 같아졌습니다. yunsuk1590 차의 블루투스는 아직 시험하지 않았습니다.
- **다음**: [아두이노 담당 작업 안내](arduino-brief.md)의 「Claude가 이어서 작업할 때」.
  1. README 「6. 시험 방법과 결과」의 바닥 시험 줄 맞추기
  2. 발표회가 끝나면 장애물 부품 조사
  - 발표회가 끝나면 바로 **장애물 부품 조사**를 시작합니다(11/11 sunbell, 이음제 콘텐츠 2 「장애물 제어」). 속도 단계 만들기도 발표회 뒤에 합니다. → 안건 「개발 10 · 장애물 제어」
- **예비 코드**: 담당자 코드가 발표회 전에 준비되지 못할 때를 대비해 sunbell이 11/9에 만들었습니다(`sunbell/arduino` 브랜치의 `arduino/car_backup/`). 발표회 차에는 담당자 코드를 먼저 올립니다.
- **걸리는 것**: 없음(11/11 기준). 레포 코드와 발표회 차 보드의 세기가 255로 같아졌습니다. 장애물 부품은 조사 전입니다. → 안건 「개발 10 · 장애물 제어」

### 통합
**담당**: 아직 정하지 않음 · **마지막 확인**: 11/11

- **하는 일**: 몸 동작 인식 결과를 아두이노로 보내서, 실제로 차나 차단봉이 움직이게 두 쪽을 잇는 일.
- **지금**: 11/11 발표회 시연에 쓸 연결(웹캠 → 몸 동작 프로그램 → 블루투스 `COM11` → 차)을 sunbell 노트북과 sunbell 차로 이어 보았고 통과했습니다(11/11).
  - 이음제까지 맡을 통합 담당은 아직 정하지 않았습니다. sunbell과 yunsuk1590이 함께 할 수도 있습니다. → 안건 「운영 6 · 역할 나누기」
- **다음**
  - 발표 전에 USB 선 예비책(`COM9`)을 몸 동작 프로그램으로 한 번 시험하기(11/11 sunbell 결정) → 안건 「운영 7 · 11/11 발표회 시연」
  - 이음제에서 쓸 값의 모양과 연결 방법은 발표회 뒤에 다시 봅니다. → 안건 「개발 2 · 내보낼 값」, 「개발 3 · 아두이노 연결 방식」
- **시험 현황 (11/9, sunbell 노트북 확인)**: 아두이노 프로그램(Arduino IDE 2.3.10), 보드 설정, 모터 라이브러리, 키트 보드의 USB 칩(CH340) 드라이버가 이미 있어서 새로 설치할 것은 없습니다. 보드를 꽂으면 COM9로 보입니다.
- **시험 현황 (11/11, sunbell 노트북과 sunbell 차)**: HC-06과 짝을 맺었고, 나가는 포트는 `COM11`입니다. 블루투스로 보낸 `F`/`S`로 차가 약속대로 움직였습니다. 윈도우 「장치 추가」로는 포트가 생기지 않아 `DevicePairingWizard`로 짝을 맺었습니다.
- **시험 현황 (11/11, 몸 동작 프로그램과 sunbell 차)**: 바닥에서 동작을 5번 해서 차가 5번 모두 움직였습니다. 리허설 146초 동안 뒤로 사람이 지나가도 잘못 켜진 적이 없었습니다. 자세한 결과는 [몸 동작 인식 계획서](plan-motion-recognition.md)의 시험표(`sunbell/motion` 브랜치)에 있습니다.

## 4. 낱말 풀이

| 말 | 뜻 |
|---|---|
| MediaPipe(미디어파이프) | 구글이 만든 도구입니다. 카메라 영상에서 사람 몸의 관절 위치를 찾아 줍니다. 우리는 이것으로 몸 동작을 알아봅니다 |
| 아두이노 | 작은 컴퓨터 보드입니다. 프로그램을 올려서 모터나 센서를 움직입니다. RC카 키트의 두뇌입니다 |
| HC-06 | 아두이노에 붙이는 블루투스 모듈입니다. 휴대폰이나 노트북과 무선으로 글자를 주고받습니다 |
| 통합 | 몸 동작 인식 결과를 아두이노로 보내서 실제로 움직이게, 두 쪽을 잇는 일입니다 |
| 시연 | 사람들 앞에서 실제로 돌아가는 모습을 보여 주는 것입니다 |
| 기믹 | 게임의 핵심 놀이 장치입니다. 예: 동작으로 여는 차단봉 |
| 안건 | 아직 정하지 않아서 팀이 함께 정해야 하는 것입니다 |
| 레포(저장소) | 팀의 코드와 문서를 모아 두는 깃허브 공간입니다. 우리 레포는 공개라서 누구나 볼 수 있습니다 |
| 브랜치 | 레포 안의 작업 공간입니다. 각자 자기 브랜치에서 작업하면 서로 부딪히지 않습니다. 예: `sunbell/motion` |
| main | 레포의 기본 브랜치입니다. 깃허브에서 레포를 열면 처음 보이는 곳입니다 |
| PR(풀 리퀘스트) | 「내 브랜치의 작업을 main에 합쳐도 될까요?」 하고 깃허브에서 요청하는 것입니다. 다른 사람이 보고 합칩니다 |
| 커밋 / push | 커밋: 작업을 한 덩어리로 저장해 기록을 남기는 것. push: 내 컴퓨터의 커밋을 깃허브에 올리는 것 |
