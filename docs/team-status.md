## 0. 지금 가장 급한 일: 11/11 학과 발표회 시연

**11월 11일(수)** 우리 학과 일정으로 **자체 최종발표회**가 있습니다. 이때 **몸 동작 인식으로 차가 움직이는 모습**을 보여 줘야 합니다. 11/5 기준 6일 남았습니다.

시연 흐름은 이렇게 하기로 했습니다(11/5 sunbell 결정, [팀 결정 기록](team-decisions.md)의 「11/11 학과 발표회 시연」).

```
웹캠 → [몸 동작 인식] → [글자 하나 보내기] → (HC-06 블루투스) → [아두이노: 글자를 받아 움직이기] → 차
       └──── sunbell 윈도우 노트북 ────┘                        └──── yunsuk1590이 새로 쓰는 코드 ────┘
```

- **정해진 것**: 보여 줄 것은 **차**(차단봉은 하지 않음) / sunbell 윈도우 노트북 + HC-06 블루투스, 예비로 USB 선 / 아두이노 코드는 yunsuk1590이 새로 씀
- **11/8에 더 정해진 것**(sunbell): 「보낼 글자 약속」은 `F` = 앞으로, `S` = 멈춤입니다. 차는 `F`를 받으면 정해진 시간만 앞으로 가고 스스로 멈춥니다. 아두이노 코드는 블루투스와 USB 선 양쪽에서 같은 글자를 받습니다.
- **아직 정할 것**: `F`를 받고 몇 초 갈지, 차가 가는 도중 `F`가 또 오면 어떻게 할지, 어떤 몸 동작으로 움직일지, 언제 모여 이어 볼지, 예비책 → 안건 「운영 7 · 11/11 발표회 시연」
- **새로 만들어야 하는 곳 두 군데**
  1. 몸 동작 인식이 동작을 알아보면 **글자 하나를 블루투스로 보내는 부분** (sunbell 노트북 쪽)
  2. 그 글자를 받아 **차를 움직이는 아두이노 코드** (yunsuk1590, [아두이노 담당 작업 안내](arduino-brief.md)의 「첫 할 일 ②」)

## 2. 파트별 상태

### 몸 동작 인식 (MediaPipe)
**담당**: sunbell · **마지막 확인**: 11/8 (`sunbell/motion` 브랜치의 커밋 `19ad876` 기준)

- **하는 일**: 웹캠 영상에서 체험자의 몸 동작(예: 두 팔 들기, 몸 기울이기)을 알아봅니다.
- **지금**: 「첫 번째 목표」(동작을 제대로 알아보는지 화면으로 확인하기)의 5단계 중 **1~4단계가 끝났습니다**(4단계는 11/5에 마침).
  - 4단계는 「떨림 방지」입니다. 인식 결과가 한순간 튀어도 화면의 결과가 흔들리지 않게 합니다. 11/5 sunbell 화면 확인에서 굼뜨지 않았고, 화면 밖으로 나가면 「동작 없음」이 제대로 떴습니다. 부스 리허설 때 다시 확인합니다.
  - 알아본 결과를 **밖으로 보내는 기능은 아직 없습니다.**
- **다음**: 원래 순서는 5단계(속도 다듬기) → 첫 번째 목표 완료 → 「두 번째 목표」(알아본 결과를 다른 프로그램이 받을 수 있는 값으로 내보내기)입니다.
  - 11/8에 sunbell이 11/11 발표회를 위해, 알아본 결과를 **글자 하나로 블루투스에 보내는 부분**을 바로 시작하기로 했습니다.
- **걸리는 것**: 맥에서는 아직 한 번도 실행해 보지 않았습니다. → 안건 「개발 6 · 팀원 컴퓨터」 (발표회는 sunbell 윈도우 노트북으로 하므로 발표회에는 영향이 없습니다.)
- 자세히: [몸 동작 인식 계획서](plan-motion-recognition.md)

### 아두이노
**담당**: yunsuk1590 · **마지막 확인**: 11/8 (레포 기준)

- **하는 일**: 노트북이 보낸 명령을 받아 차(그리고 만들기로 정하면 차단봉)를 움직이는 아두이노 프로그램과 배선.
- **지금**: 키트 조립과 시험(앞뒤 이동, 스마트폰 앱 조종)은 끝났습니다. 팀 레포에는 아직 아두이노 코드가 없습니다.
- **다음**: [아두이노 담당 작업 안내](arduino-brief.md)의 「3. 첫 할 일」. 11/11 발표회에 필요한 일부터 합니다.
  1. 맥에 아두이노 프로그램 설치
  2. 노트북이 보낸 글자를 받아 차를 움직이는 코드 새로 쓰기
  3. sunbell 노트북과 이어 보는 시험(함께 모여서)
  - 속도 단계 만들기와 차단봉 부품 조사는 **발표회 뒤로** 미뤘습니다.
- **걸리는 것**: `F`를 받고 몇 초 갈지와 언제 모여 이어 볼지 정해야 합니다. → 안건 「운영 7 · 11/11 발표회 시연」 「보낼 글자 약속」은 11/8에 sunbell이 정했습니다. (팀 문서 PR이 합쳐지기를 기다리지 않고 바로 시작합니다.)

| 브랜치 | 레포 안의 작업 공간입니다. 각자 자기 브랜치에서 작업하면 서로 부딪히지 않습니다. 예: `sunbell/motion` |
| main | 레포의 기본 브랜치입니다. 깃허브에서 레포를 열면 처음 보이는 곳입니다 |
| PR(풀 리퀘스트) | 「내 브랜치의 작업을 main에 합쳐도 될까요?」 하고 깃허브에서 요청하는 것입니다. 다른 사람이 보고 합칩니다 |
| 커밋 / push | 커밋: 작업을 한 덩어리로 저장해 기록을 남기는 것. push: 내 컴퓨터의 커밋을 깃허브에 올리는 것 |
