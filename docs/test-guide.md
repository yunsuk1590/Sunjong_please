## 기본 세팅 (시험마다 먼저 합니다)

### 가 · PowerShell을 여는 법

이 문서의 명령은 모두 **Windows PowerShell**(파란 창)에 붙여 넣어 실행합니다. 두 가지 중 편한 쪽으로 엽니다.

- **★ 폴더에서 바로 열기:** 파일 탐색기에서 아래 「나」의 폴더를 엽니다. 창 위쪽의 주소(경로)가 보이는 칸을 한 번 클릭하고, 글자를 지운 뒤 `powershell`이라고 치고 Enter를 누릅니다. 그 폴더에서 바로 열립니다.
- **시작 메뉴에서 열기:** 시작 버튼을 누르고 `PowerShell`을 검색해서 「Windows PowerShell」을 엽니다. 이때는 아무 폴더에서나 열리므로, 아래 「나」의 `cd` 명령을 먼저 붙여 넣어 폴더를 옮깁니다.
- 붙여 넣기는 창에서 마우스 오른쪽 클릭이나 Ctrl+V입니다. Enter를 눌러야 실행됩니다.
- 실행 중인 명령을 멈추려면 Ctrl+C입니다. 창을 닫아도 멈춥니다.

### 다 · 차 보드의 포트(COM 번호) 확인

차를 USB 선으로 꽂거나 블루투스로 짝을 맺으면 윈도우가 `COM9`처럼 번호를 붙입니다. 시험 명령의 `-Port` 자리에 이 번호를 넣습니다. 번호는 **다시 짝을 맺거나 다른 USB 구멍에 꽂으면 바뀝니다.** 그래서 시험 전에 확인합니다. 붙여 넣어 실행합니다.

```powershell
Get-CimInstance Win32_PnPEntity | Where-Object { $_.Name -match '\(COM\d+\)' } | Select-Object Name
```

| 나오는 이름 | 뜻 |
|---|---|
| `USB-SERIAL CH340(COM9)` | **차 보드의 USB 포트.** 11/23 기준 my의 메인 차(`IEUMCAR2`)는 `COM9` |
| `표준 Bluetooth에서 직렬 링크(COM11)` | 블루투스 **나가는** 포트. 11/23 기준 메인 차는 `COM11`. 같은 이름이 여럿(`COM3`, `COM4`, `COM10`…)이면 다른 장치의 것이라서, 어느 것이 차인지 모르겠으면 `COM11`부터 시험합니다 |
| 줄이 아예 없음 | USB 선이 안 꽂혔거나 차 보드 전원이 꺼진 것입니다. 11/23에 이런 일이 있었습니다 |

### 라 · 시험 전에 매번 확인 (체크리스트)

- [ ] **차는 바닥에 놓습니다.** 책상 위에서는 하지 않습니다.
- [ ] **앞뒤 약 1 m(긴 시험은 2 m)를 비웁니다.** 커브를 3~4초 누르면 원이 크게 돌 수 있어서 사방 1.5 m가 필요합니다.
- [ ] **건전지가 모두 끼워졌는지 봅니다.** 한 개만 빠져도 두 바퀴 힘이 달라져 시험이 틀어집니다.
- [ ] **USB 선에 여유를 줍니다.** 차가 선을 당기면 연결이 끊길 수 있습니다(11/23에 한 번 끊김).
- [ ] **COM 포트를 쓰는 다른 프로그램을 닫습니다.** Arduino IDE의 시리얼 모니터, 앞서 돌린 시험 창 등. 한 포트는 한 프로그램만 열 수 있습니다.
- [ ] 차 **앞 20 cm 안에 물건**이 없는지 봅니다. 지금 차는 앞이 막히면 앞으로 가지 않습니다(막힘 기능 켜짐). **평평하게 마주 본 면에서만 믿을 수 있고, 비스듬한 면은 못 보고 부딪힙니다**(11/23 시험).

### 마 · 차 코드를 올리는 법 (필요할 때만)

코드를 고쳤거나 새 차에 올릴 때만 합니다. 평소 시험에는 필요 없습니다. `Sunjong_arduino` 폴더의 PowerShell에서 실행합니다(`COM9`는 위 「다」에서 확인한 차 보드 USB 포트로 바꿉니다).

```powershell
& "D:\Program\Arduino IDE\resources\app\lib\backend\resources\arduino-cli.exe" compile --fqbn arduino:avr:uno -u -p COM9 arduino/car_race
```

- 「프로그램 저장 공간 …바이트(22%)를 사용」이 나오면 올라간 것입니다. 오류가 없는지 봅니다. 올리는 데 10~20초 걸립니다.
- Arduino IDE로 올려도 됩니다. 차 코드 README 「3」에 있습니다.
- 올린 뒤 보드는 처음 상태로 돌아가서, 시험 명령을 처음 실행하면 「car_race 시작…」이 나옵니다.

### 바 · 안 될 때

| 증상 | 확인할 것 |
|---|---|
| 「포트를 열 수 없다」, 「Access denied」 | 시리얼 모니터나 앞서 돌린 시험 창이 그 포트를 쓰고 있습니다. 닫고 다시 합니다 |
| 「포트가 없다」, 「cannot find port」 | USB 선, 차 보드 전원, 포트 번호(위 「다」)를 봅니다 |
| 화면에 글자가 안 나오고 차도 안 움직임 | 포트 번호가 다른 장치의 것인지 봅니다. 블루투스는 화면에 로그가 나오지 않는 것이 정상입니다 |
| 시험 도중 포트가 닫혀서 멈춤 | USB 선이 당겨지거나 빠진 것입니다. 선을 정리하고 다시 합니다 |

## 1 · 노트북 혼자 켜 보기

**무엇을 보나**: 카메라가 열리고 몸 동작 4개가 잘 잡히는지. 차는 쓰지 않습니다.

**준비**: 전원을 꽂고 「최고 성능」으로 둡니다. 밝은 곳에서, 카메라에 상반신이 다 보이게 섭니다.

**명령**: `motion` 폴더에서 `run.bat`을 더블클릭합니다. 포트를 적지 않았으니 글자는 보내지 않고 화면에만 나옵니다.

**통과 기준**
- 화면 위 `CAMERA`가 25 이상이고, `LOOP`가 그와 비슷합니다.
- 두 팔 들기, 왼팔 들기, 오른팔 들기, 팔 양옆으로 벌리기를 하면 화면 아래 큰 글씨가 `ARMS_UP`, `LEFT_UP`, `RIGHT_UP`, `T_POSE`로 바뀝니다. 팔을 내리면 `NONE`입니다.
- 끄는 법: 창에서 `q` 또는 `Esc`.

**지난 결과**: my와 test1 모두 초당 약 29.8장(11/20), test2도 29.8장(11/23). my는 절전 모드에서 17.8장으로 떨어졌습니다.

## 2 · 노트북 사이 길 확인

**무엇을 보나**: 같은 와이파이의 두 노트북이 서로 글자를 주고받을 수 있는지. 차, 카메라는 쓰지 않습니다.

**준비**: 두 노트북을 같은 와이파이에 잇습니다. P1이 될 노트북에서 `ipconfig`로 주소를 알아 둡니다(문서에는 적지 않습니다).

**명령**: 두 노트북 모두 `motion` 폴더에서 PowerShell을 엽니다.

P1(받는 쪽):
```powershell
.\.venv\Scripts\python.exe net_check.py listen
```
P2(보내는 쪽). `P1주소` 자리에 P1의 주소를 넣습니다:
```powershell
.\.venv\Scripts\python.exe net_check.py send P1주소
```

**통과 기준**
- P2 화면에 「글자 N번 보냄, 답 M번 받음」이 나오고 **N = M**입니다.
- P1을 Ctrl+C로 끄면 나오는 「0.3초 넘게 끊긴 횟수」가 0에 가깝습니다.
- 답이 0이면: P1에서 「네트워크 접근 허용」을 했는지, 주소가 맞는지, 같은 와이파이인지 봅니다.
- **주소는 `ipconfig`의 「IPv4 주소」 줄입니다.** 바로 아래 「기본 게이트웨이」(와이파이 공유기의 주소)를 적으면 양쪽 모두 답이 0이 됩니다(11/23 test2에서 실제로 겪음).

**지난 결과**: 11/19 학교 와이파이, 67번 보내 67번 받음, 왕복 평균 16 ms(가장 긴 것 138 ms).

## 3 · 차만 시험하기 (USB)

**무엇을 보나**: 차가 글자대로 움직이는지(직진, 돌기, 커브, 멈춤). 몸 동작 프로그램은 쓰지 않고, 시험 스크립트가 컨트롤러처럼 글자를 보냅니다.

**준비**
- 위 「기본 세팅」의 「가」~「라」를 합니다. **`Sunjong_arduino` 폴더**에서 PowerShell을 엽니다(시험 스크립트 `send_keys.ps1`은 `sunbell/arduino` 브랜치에 있습니다).
- 차 보드 USB 선을 꽂고, 포트 번호(「다」)를 확인합니다. my의 메인 차는 `COM9`입니다.

**기본 명령** (붙여 넣고, `COM9`와 `-Plan "…"` 안의 글자만 바꿉니다):
```powershell
powershell -ExecutionPolicy Bypass -File arduino/car_race/tools/send_keys.ps1 -Port COM9 -Plan "W:1000;S:800"
```

- 화면에 `ms` 시간과 함께 차의 로그(`바퀴 왼 255 오 239` 같은 줄)가 나옵니다. 끝나면 「끝」이 나오고 PowerShell로 돌아옵니다.
- `-Plan`은 「글자:누르는 시간(ms)」를 `;`로 이은 것입니다. `W+A`는 두 글자를 동시에 누른 것입니다. 단계 사이에 0.9초씩 쉽니다.

**시험마다 `-Plan`만 바꿉니다.** 붙여 넣을 명령은 위 기본 명령에서 `-Plan "…"` 부분만 아래 것으로 바꿉니다.

| 무엇을 보나 | `-Plan` | 통과 기준 |
|---|---|---|
| 직진·후진 | `W:1000;S:800` | 크게 휘지 않음. 로그 `바퀴 왼 255 오 255`(보정 없음, 11/23 저녁부터) |
| 제자리 돌기 | `A:500;D:500` | 양쪽으로 비슷하게 돎 |
| **지금 기본 커브**(번호 없이) | `W+A:6000` 과 `W+D:6000` | **6초 동안 한 바퀴쯤 돌아 원이 닫힘.** 지름은 테이프 두 개(출발점과 가장 멀어진 곳)를 붙이고 줄자로 잼. 왼쪽 약 62 cm, 오른쪽 약 63 cm(11/23 저녁) |
| 커브 번호 고르기 | `3:300;W+A:6000` | 맨 앞 숫자(`1`~`9`)를 바꿔 가며 6초 커브의 원 지름(cm)을 잼. 한 번에 한 쪽만 시험함. 지름은 같은 번호도 ±10 cm쯤 흔들림 |
| 직진 쏠림 | `W:3000` | 3초 뒤 옆으로 쏠린 cm를 잼(오른쪽/왼쪽 표시). 11/23 저녁: 오른쪽 12~17 cm(보정 없음). 블루투스(`-Port COM11`, USB 뽑음)로 하는 것이 실제와 같음 |
| 시간 제한 | `W:600` | 글자가 끊긴 뒤 약 0.2~0.3초 만에 `바퀴 왼 0 오 0` |
| 멈춤 글자 | `W:600;X:450;A:500;Z:450;W:500;A+X:450;A:300;Z:450;Q:600` 과 `-GapMs 0` | `X`/`Z` 뒤 바로 섬. `A+X`는 직진만 끊기고 돌기만 남음 |
| 속도 재기 | `W:3000` | 출발 전과 선 뒤의 차 앞바퀴 위치를 바닥에 표시하고 거리를 잼. 11/23: 약 93 cm(초당 약 30 cm) |
| 초음파(평평한 면) | `W:2500;S:800;W:600` | 앞 약 50 cm에 평평한 물건을 정면으로 세움. 17 cm쯤에서 `앞이 막힘`이 뜨고 섬. 막힌 동안 `W`는 무시, `S`로 빠지면 `앞이 열림`, 마지막 `W`로 다시 감 |

- `-GapMs 0`은 명령 끝에 붙입니다(단계 사이에 쉬지 않음): `… -Plan "…" -GapMs 0`
- **커브는 3~4초씩 눌러야 원이 보입니다.** 1.5초는 너무 짧습니다(11/23).
- 커브 짝은 9가지(바깥 / 안쪽 바퀴 속도)입니다: `1` = 255/190, `2` = 255/150, `3` = 255/110, `4` = 255/70, `5` = 200/95, `6` = 255/0, `7` = 255/35, `8` = 255/90, `9` = 255/165. **기본은 왼쪽 3번, 오른쪽 2번**입니다(2026-11-23 저녁 sunbell 결정. 처음에 정했던 7번/8번은 지름이 약 30~35 cm로 선회 수준이라 넓힘. 같은 번호로는 오른쪽이 더 좁게 돌아 따로 정함). 직진 보정은 지금 없음(오른쪽 100%, 왼쪽 100%)입니다.
- 포트를 열 때마다 보드가 다시 켜져서 커브 번호가 기본값으로 돌아갑니다. 번호를 바꿔 보려면 `-Plan` 맨 앞에 넣습니다.
- 더 많은 시험과 각 값의 뜻은 차 코드 README 「5」, 「8」에 있습니다.

**지난 결과**(sunbell 차, AA 건전지, 바닥)
- 직진은 오른쪽 94% 보정으로 곧게 감. 제자리 돌기 190 좋음. 멈춤 글자 `X`/`Z`를 3번 연달아 받아도 정상(11/20).
- **11/23 커브:** 낮에 왼쪽 7번, 오른쪽 8번으로 맞췄으나 6-2에서 「거의 선회 수준」이라 저녁에 **왼쪽 3번, 오른쪽 2번**으로 넓힘(6초 원 지름 약 62~63 cm). 오른쪽 9번은 지름이 65~115 cm로 흔들려 뺌.
- **11/23 속도:** `W` 3초에 약 93 cm(초당 약 30 cm).

## 4 · 노트북 1대 + 차

**무엇을 보나**: 몸 동작으로 차가 움직이고, 팔을 내리면 서는지. 한 사람이 네 동작을 모두 합니다.

**준비**: 「1」과 「3」이 통과한 노트북과 차. USB 선이면 차 보드 USB 포트, 블루투스면 「나가는」 포트를 씁니다(my: USB `COM9`, 블루투스 `COM11`). 차를 바닥에 두고 앞뒤 1 m를 비웁니다. **켤 때는 팔을 내리고 있습니다.**

**명령** (`motion` 폴더에서):
```powershell
.\run.bat --port COM9 --letters ARMS_UP=W,T_POSE=S,LEFT_UP=A,RIGHT_UP=D
```

**통과 기준**
- 두 팔 들기 = 앞, T자 = 뒤, 왼팔 = 왼쪽 돌기, 오른팔 = 오른쪽 돌기.
- 팔을 내리면 곧 섭니다.
- 화면 `OUTPUT` 줄이 `COM9 OPEN`이고 `sent` 숫자가 늘어납니다. `dropped`가 늘면 포트가 열리지 않은 것입니다.
- `q`로 끄면 차가 바로 섭니다.

- 노트북 1대로는 `W`와 `A`를 **동시에** 보낼 수 없습니다(동작이 한 번에 하나만 켜짐). 커브는 「3」이나 「5」에서 봅니다.

## 5 · 노트북 2대 + 차 (USB)

**무엇을 보나**: 실제 경기 모양 그대로, 두 사람이 한 차를 함께 모는지. P1이 앞뒤, P2가 좌우를 맡습니다.

**준비**
- 「2」가 통과한 두 노트북. 차와 이어지는 노트북이 P1입니다.
- P1에서 `ipconfig`로 주소를, P2에서도 `ipconfig`로 주소를 알아 둡니다(문서에는 적지 않습니다). 와이파이가 주는 번호라 바뀔 수 있어서 **시험 직전에 다시 확인**합니다.
- 차를 USB 선으로 P1에 잇고, 바닥에 두고 앞뒤 1 m를 비웁니다. 두 사람 모두 팔을 내리고 켭니다.

**명령** (두 노트북 모두 `motion` 폴더에서):

P1(차와 연결, P2의 글자를 받아 함께 넘김):
```powershell
.\run.bat --port COM9 --role P1 --listen --allow-from P2주소
```
P2(P1에게 보냄):
```powershell
.\run.bat --role P2 --send-to P1주소
```

- `--allow-from`은 P2 노트북이 보낸 글자만 받게 합니다. 빼면 같은 와이파이의 아무 기기가 보낸 글자도 차로 넘어갑니다.
- 팔을 내린 뒤 꺼지기까지 기다리는 시간은 기본 0.2초입니다(11/20 sunbell). 따로 적지 않아도 됩니다.

**통과 기준**
- P2 화면 `OUTPUT` 줄이 `UDP … OK 16ms`처럼 `OK`입니다. `NO REPLY`면 P1이 받지 못하는 것입니다.
- P1 화면 `NET` 줄의 `recv` 숫자가 늘어납니다.
- P1만 팔을 들면 앞뒤만, P2만 팔을 들면 좌우만 움직입니다. 둘이 함께 들면 커브를 돕니다.
- **한 사람이 팔을 내리면 그 사람이 맡은 움직임만 멈춥니다.** 다른 사람의 움직임은 이어집니다.
- P1을 끄면 차가 바로 섭니다(P1이 `XZ`를 보냄). P2를 끄면 좌우만 멈춥니다(P2가 `Z`를 보냄).

**지난 결과**: **11/20 통과**(my = P1, test1 = P2, 학교 와이파이, 차는 USB `COM9`). 두 노트북 모두 초당 약 29.8장. 158초 동안 P2가 보낸 글자 121번 가운데 120번이 왔습니다(1번은 와이파이에서 사라진 것으로 짐작). 한 사람이 팔을 내리면 그 축만 멈췄고, 끄면 바로 섰습니다. 서는 시간은 sunbell이 「적당한 것 같아」라고 했습니다.

## 6 · 노트북 2대 + 차 (블루투스)

### 6-1 · 차만 블루투스로 (노트북 몸 동작 프로그램 없이)

**무엇을 보나**: 차가 USB 선 없이 블루투스 글자만으로도 「3」과 똑같이 달리고 서는지. 몸 동작 프로그램은 쓰지 않고, 「3」의 시험 스크립트가 블루투스로 글자를 보냅니다. 이것이 되면 6-2에서 문제가 나도 차 쪽 탓이 아닙니다.

**준비**
- 위 「기본 세팅」의 「가」~「라」를 합니다. **`Sunjong_arduino` 폴더**에서 PowerShell을 엽니다.
- **차에서 USB 선을 뽑습니다.** 차 전원은 건전지로 켜져 있어야 합니다.
- 「다」의 명령으로 블루투스 「나가는」 포트를 확인합니다(my의 메인 차 `IEUMCAR2`는 11/23 기준 `COM11`). 짝을 새로 맺었다면 번호가 바뀝니다.

**명령** (붙여 넣고 `COM11`만 바꿉니다):
```powershell
powershell -ExecutionPolicy Bypass -File arduino/car_race/tools/send_keys.ps1 -Port COM11 -Plan "W:1500;W+A:3000;W+D:3000;S:800"
```

**통과 기준**
- 차가 USB 때와 똑같이 직진, 왼쪽 커브, 오른쪽 커브, 후진을 합니다.
- 글자를 끊으면 0.3초쯤 뒤에 섭니다.
- 달리다가 끊기듯 멈칫하지 않습니다.
- **화면에는 차의 로그가 나오지 않습니다.** 블루투스로는 로그를 못 읽어서 정상입니다. 눈으로만 봅니다.
- 이 스크립트를 블루투스 포트로 쓰는 것은 **아직 시험하지 못했습니다**(11/23). 포트가 안 열리면 바로 알려 주세요.

### 6-2 · 노트북 2대 + 차 (블루투스)

**무엇을 보나**: 「5」를 USB 선 없이 블루투스로 해도 같은지. 이음제는 이 모양으로 합니다.

**준비**: 「5」와 같고, 차에서 USB 선을 뽑습니다. 「6-1」이 통과한 뒤에 합니다. P1 노트북이 차와 짝을 맺어 「나가는」 포트를 알고 있어야 합니다([노트북 세팅 안내](laptop-setup.md) 「6」). `motion` 폴더에서 PowerShell을 엽니다(「기본 세팅」 「나」).

**명령**: 「5」의 P1 명령에서 `--port`만 블루투스 포트로 바꿉니다(my는 `COM11`).
```powershell
.\run.bat --port COM11 --role P1 --listen --allow-from P2주소
```

**통과 기준**: 「5」와 같습니다. 그리고
- 차가 달리다가 끊기듯 멈칫하지 않는지 봅니다. 자주 멈칫하면 차의 시간 제한(0.3초)을 늘릴지 sunbell과 정합니다.
- P1을 끌 때 `--port`가 블루투스여도 차가 바로 서는지 봅니다.

**P2를 맥으로 할 때** (yunsuk1590 맥, **11/23 저녁 통과**): 맥의 **「터미널」 앱**(Claude 앱 안의 터미널은 카메라 권한이 안 잡힘)에서 `Sunjong_motion/motion` 폴더로 가서 실행합니다. 맥 주소는 `ipconfig getifaddr en0`로 찾습니다.
```
./run.command --role P2 --send-to my주소
```
- P1(my)의 `--allow-from` 자리에는 맥의 주소를 넣습니다.
- **차를 몰기 전에 길 확인(「2」)을 맥에서 꼭 한 번 합니다**: `.venv/bin/python net_check.py send my주소`. 11/23에 와이파이가 막 연결된 직후 처음 몇 초 동안 글자가 안 나갔고(`No route to host`), 바로 다시 하니 모두 통과했습니다(yunsuk1590 보고).

**지난 결과**: **11/23 통과**(my = P1 블루투스 `COM11`, test2 = P2). 약 5분 동안 멈칫 없이 달렸고, 한 사람이 팔을 내리면 그 축만 멈췄고, `q`로 끄면 바로 섰습니다. 자세한 숫자는 「8」. 프로그램을 켠 뒤 블루투스 포트가 열리기까지 몇 초 걸리니, my 화면 `OUTPUT` 줄이 `COM11 OPEN`이 된 뒤에 시작합니다.

## 9 · 낱말 풀이

| 말 | 뜻 |
|---|---|
| P1 / P2 | 협동 레이싱의 두 역할. P1은 앞뒤(두 팔 들기 `W`, T자 `S`), P2는 좌우(왼팔 `A`, 오른팔 `D`) |
| 멈춤 글자 | 팔을 내릴 때 보내는 글자. `X` = 앞뒤만 끔, `Z` = 좌우만 끔. 3번 연달아 보냅니다 |
| 시간 제한 | 차가 0.3초 동안 글자를 못 받으면 그 입력을 스스로 끄는 것. 연결이 끊겨도 차가 섭니다 |
| 커브 짝 | 휘며 갈 때 바깥 바퀴와 안쪽 바퀴의 속도 짝. 안쪽이 느릴수록 좁게 돕니다 |
| `-Plan` | 시험 스크립트에 주는 「글자:누르는 시간(ms)」 목록. `W+A`는 두 글자를 동시에 누른 것 |
| `ipconfig` | 윈도우에서 이 노트북의 와이파이 주소를 보는 명령 |
| UDP | 같은 와이파이의 두 노트북이 짧은 글자를 빠르게 주고받는 방법. 가끔 한 글자가 사라질 수 있습니다 |
| 나가는(Outgoing) 포트 | 노트북이 블루투스로 글자를 보낼 때 여는 COM 포트 |
| PowerShell | 윈도우에서 글자 명령을 쳐서 프로그램을 실행하는 파란 창. 시작 메뉴에서 「PowerShell」을 검색해 엽니다 |
| COM 포트(`COM9` 등) | 노트북이 USB나 블루투스 장치와 글자를 주고받는 통로의 이름. 한 번에 한 프로그램만 열 수 있습니다 |
| `cd` | PowerShell에서 폴더를 옮기는 명령. `cd 폴더경로` |
| 앞 막힘 | 차가 앞 20 cm 안에 평평한 물건이 있다고 알아채면 앞으로 안 가는 기능. 지금 켜져 있고, 비스듬한 면은 못 알아봅니다 |
