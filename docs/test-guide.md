# 시험 안내 (협동 레이싱)

> **이 문서는?** 이음제(11/28) 협동 레이싱이 제대로 도는지 **어떤 순서로, 무엇을, 어떻게 시험하는지**를 한곳에 모은 안내입니다. 시험마다 「준비 → 명령 → 통과 기준 → 지난 결과」 순서로 썼습니다.
> - **누가 읽나요?** 시험하는 팀원 누구나. 팀장 sunbell.
> - **작성**: 2026-11-21, sunbell(Claude 도움). 결과는 이 날짜까지의 것입니다.
> - **노트북을 먼저 맞춰야 합니다.** 파이썬, 코드 받기, 설치, 블루투스 짝 맺기는 [노트북 세팅 안내](laptop-setup.md)에 있습니다.
> - 자세한 설정은 각 README가 원본입니다: [몸 동작 README](https://github.com/yunsuk1590/Sunjong_please/blob/sunbell/motion/motion/README.md)(`sunbell/motion` 브랜치), [차 코드 README](https://github.com/yunsuk1590/Sunjong_please/blob/sunbell/arduino/arduino/car_race/README.md)(`sunbell/arduino` 브랜치). 이 문서와 다르면 README를 믿어 주세요.
> - **공개 레포입니다.** 명령에 들어가는 IP 주소는 `P1주소`처럼 비워 두고, 시험 결과에도 적지 않습니다.
> - 처음 보는 말은 맨 아래 「9 · 낱말 풀이」에 있습니다.

## 0 · 시험 순서 한눈에 보기

아래로 갈수록 이어 붙이는 부분이 많아집니다. 앞 단계가 안 되면 다음 단계로 가지 않습니다.

| 번호 | 시험 | 필요한 것 | 상태(11/21) |
|---|---|---|---|
| 1 | 노트북 혼자 켜 보기 | 노트북 1대 | my, test1 끝 / test2 아직 |
| 2 | 노트북 사이 길 확인 | 노트북 2대, 같은 와이파이 | 끝(11/19) |
| 3 | 차만 시험하기 | my + 차(USB 선) | 진행 중(커브 짝 고르기) |
| 4 | 노트북 1대 + 차 | 노트북 1대 + 차 | 따로 적은 결과 없음(「5」가 통과해서 건너뛰어도 됨) |
| 5 | 노트북 2대 + 차 (USB) | 노트북 2대 + 차 | **끝(11/20)** |
| 6 | 노트북 2대 + 차 (블루투스) | 노트북 2대 + 차 | 아직 |
| 7 | 트랙 리허설 | 위 전부 + 트랙 | 아직(맵을 다시 정하는 중) |

## 1 · 노트북 혼자 켜 보기

**무엇을 보나**: 카메라가 열리고 몸 동작 4개가 잘 잡히는지. 차는 쓰지 않습니다.

**준비**: 전원을 꽂고 「최고 성능」으로 둡니다. 밝은 곳에서, 카메라에 상반신이 다 보이게 섭니다.

**명령**: `motion` 폴더에서 `run.bat`을 더블클릭합니다. 포트를 적지 않았으니 글자는 보내지 않고 화면에만 나옵니다.

**통과 기준**
- 화면 위 `CAMERA`가 25 이상이고, `LOOP`가 그와 비슷합니다.
- 두 팔 들기, 왼팔 들기, 오른팔 들기, 팔 양옆으로 벌리기를 하면 화면 아래 큰 글씨가 `ARMS_UP`, `LEFT_UP`, `RIGHT_UP`, `T_POSE`로 바뀝니다. 팔을 내리면 `NONE`입니다.
- 끄는 법: 창에서 `q` 또는 `Esc`.

**지난 결과**: my와 test1 모두 초당 약 29.8장(11/20). my는 절전 모드에서 17.8장으로 떨어졌습니다.

## 2 · 노트북 사이 길 확인

**무엇을 보나**: 같은 와이파이의 두 노트북이 서로 글자를 주고받을 수 있는지. 차, 카메라는 쓰지 않습니다.

**준비**: 두 노트북을 같은 와이파이에 잇습니다. P1이 될 노트북에서 `ipconfig`로 주소를 알아 둡니다(문서에는 적지 않습니다).

**명령**: 두 노트북 모두 `motion` 폴더에서 PowerShell을 엽니다.

P1(받는 쪽):
```powershell
.\.venv\Scripts\python.exe net_check.py listen
```
P2(보내는 쪽). `P1주소` 자리에 P1의 주소를 넣습니다:
```powershell
.\.venv\Scripts\python.exe net_check.py send P1주소
```

**통과 기준**
- P2 화면에 「글자 N번 보냄, 답 M번 받음」이 나오고 **N = M**입니다.
- P1을 Ctrl+C로 끄면 나오는 「0.3초 넘게 끊긴 횟수」가 0에 가깝습니다.
- 답이 0이면: P1에서 「네트워크 접근 허용」을 했는지, 주소가 맞는지, 같은 와이파이인지 봅니다.

**지난 결과**: 11/19 학교 와이파이, 67번 보내 67번 받음, 왕복 평균 16 ms(가장 긴 것 138 ms).

## 3 · 차만 시험하기 (USB)

**무엇을 보나**: 차가 글자대로 움직이는지(직진, 돌기, 커브, 멈춤). 몸 동작 프로그램은 쓰지 않고, 시험 스크립트가 컨트롤러처럼 글자를 보냅니다.

**준비**
- 차 코드 브랜치가 있는 노트북(my의 `Sunjong_arduino` 폴더)에서 합니다. 시험 스크립트 `send_keys.ps1`은 `sunbell/arduino` 브랜치에 있습니다.
- **차를 바닥에 놓고 앞뒤 약 1 m를 비웁니다.** 앞 20 cm 안에 물건이 있으면 앞으로 가지 않습니다.
- USB 선을 꽂고, Arduino IDE의 시리얼 모니터는 닫습니다(한 포트는 한 프로그램만 엽니다).

**명령** (my의 차 보드 USB 포트는 `COM9`):
```powershell
powershell -ExecutionPolicy Bypass -File arduino/car_race/tools/send_keys.ps1 -Port COM9 -Plan "W:1000;S:800"
```

`-Plan`만 바꿔서 여러 시험을 합니다. 자주 쓰는 것:

| 무엇을 보나 | `-Plan` | 통과 기준 |
|---|---|---|
| 직진·후진 | `W:1000;S:800` | 한쪽으로 휘지 않음. 로그 `바퀴 왼 255 오 239` |
| 제자리 돌기 | `A:500;D:500` | 양쪽으로 비슷하게 돎 |
| 커브 짝 고르기 | `6:200;W+A:1500;W+D:1500` | 맨 앞 숫자(`1`~`6`)를 바꿔 가며, 왼쪽과 오른쪽이 같게, 트랙에 맞는 크기로 도는지 |
| 시간 제한 | `W:600` | 글자가 끊긴 뒤 약 0.2~0.3초 만에 `바퀴 왼 0 오 0` |
| 멈춤 글자 | `W:600;X:450;A:500;Z:450;W:500;A+X:450;A:300;Z:450;Q:600` 과 `-GapMs 0` | `X`/`Z` 뒤 바로 섬. `A+X`는 직진만 끊기고 돌기만 남음 |

- 커브 짝 6가지(바깥 / 안쪽 바퀴 속도): `1` = 255/190, `2` = 255/150(지금 기본값, 너무 약함), `3` = 255/110, `4` = 255/70, `5` = 200/95, `6` = 255/0. **다음 시험 순서는 6 → 3 → 5번**입니다. 어느 번호를 기본으로 할지는 sunbell이 정합니다.
- 포트를 열 때마다 보드가 다시 켜져서 커브 번호가 기본값으로 돌아갑니다. 시험마다 `-Plan` 맨 앞에 번호를 넣습니다.
- 더 많은 시험과 각 값의 뜻은 차 코드 README 「5」, 「8」에 있습니다.

**지난 결과**(sunbell 차, AA 건전지, 바닥): 직진은 오른쪽 94% 보정으로 곧게 감. 제자리 돌기 190 좋음. 커브 2번은 너무 약함. 멈춤 글자 `X`/`Z`를 3번 연달아 받아도 정상(11/20, sunbell 눈 확인).

## 4 · 노트북 1대 + 차

**무엇을 보나**: 몸 동작으로 차가 움직이고, 팔을 내리면 서는지. 한 사람이 네 동작을 모두 합니다.

**준비**: 「1」과 「3」이 통과한 노트북과 차. USB 선이면 차 보드 USB 포트, 블루투스면 「나가는」 포트를 씁니다(my: USB `COM9`, 블루투스 `COM11`). 차를 바닥에 두고 앞뒤 1 m를 비웁니다. **켤 때는 팔을 내리고 있습니다.**

**명령** (`motion` 폴더에서):
```powershell
.\run.bat --port COM9 --letters ARMS_UP=W,T_POSE=S,LEFT_UP=A,RIGHT_UP=D
```

**통과 기준**
- 두 팔 들기 = 앞, T자 = 뒤, 왼팔 = 왼쪽 돌기, 오른팔 = 오른쪽 돌기.
- 팔을 내리면 곧 섭니다.
- 화면 `OUTPUT` 줄이 `COM9 OPEN`이고 `sent` 숫자가 늘어납니다. `dropped`가 늘면 포트가 열리지 않은 것입니다.
- `q`로 끄면 차가 바로 섭니다.

- 노트북 1대로는 `W`와 `A`를 **동시에** 보낼 수 없습니다(동작이 한 번에 하나만 켜짐). 커브는 「3」이나 「5」에서 봅니다.

## 5 · 노트북 2대 + 차 (USB)

**무엇을 보나**: 실제 경기 모양 그대로, 두 사람이 한 차를 함께 모는지. P1이 앞뒤, P2가 좌우를 맡습니다.

**준비**
- 「2」가 통과한 두 노트북. 차와 이어지는 노트북이 P1입니다.
- P1에서 `ipconfig`로 주소를, P2에서도 `ipconfig`로 주소를 알아 둡니다(문서에는 적지 않습니다). 와이파이가 주는 번호라 바뀔 수 있어서 **시험 직전에 다시 확인**합니다.
- 차를 USB 선으로 P1에 잇고, 바닥에 두고 앞뒤 1 m를 비웁니다. 두 사람 모두 팔을 내리고 켭니다.

**명령** (두 노트북 모두 `motion` 폴더에서):

P1(차와 연결, P2의 글자를 받아 함께 넘김):
```powershell
.\run.bat --port COM9 --role P1 --listen --allow-from P2주소
```
P2(P1에게 보냄):
```powershell
.\run.bat --role P2 --send-to P1주소
```

- `--allow-from`은 P2 노트북이 보낸 글자만 받게 합니다. 빼면 같은 와이파이의 아무 기기가 보낸 글자도 차로 넘어갑니다.
- 팔을 내린 뒤 꺼지기까지 기다리는 시간은 기본 0.2초입니다(11/20 sunbell). 따로 적지 않아도 됩니다.

**통과 기준**
- P2 화면 `OUTPUT` 줄이 `UDP … OK 16ms`처럼 `OK`입니다. `NO REPLY`면 P1이 받지 못하는 것입니다.
- P1 화면 `NET` 줄의 `recv` 숫자가 늘어납니다.
- P1만 팔을 들면 앞뒤만, P2만 팔을 들면 좌우만 움직입니다. 둘이 함께 들면 커브를 돕니다.
- **한 사람이 팔을 내리면 그 사람이 맡은 움직임만 멈춥니다.** 다른 사람의 움직임은 이어집니다.
- P1을 끄면 차가 바로 섭니다(P1이 `XZ`를 보냄). P2를 끄면 좌우만 멈춥니다(P2가 `Z`를 보냄).

**지난 결과**: **11/20 통과**(my = P1, test1 = P2, 학교 와이파이, 차는 USB `COM9`). 두 노트북 모두 초당 약 29.8장. 158초 동안 P2가 보낸 글자 121번 가운데 120번이 왔습니다(1번은 와이파이에서 사라진 것으로 짐작). 한 사람이 팔을 내리면 그 축만 멈췄고, 끄면 바로 섰습니다. 서는 시간은 sunbell이 「적당한 것 같아」라고 했습니다.

## 6 · 노트북 2대 + 차 (블루투스)

**무엇을 보나**: 「5」를 USB 선 없이 블루투스로 해도 같은지. 이음제는 이 모양으로 합니다.

**준비**: 「5」와 같고, 차에서 USB 선을 뽑습니다. P1 노트북이 차와 짝을 맺어 「나가는」 포트를 알고 있어야 합니다([노트북 세팅 안내](laptop-setup.md) 「6」).

**명령**: 「5」의 P1 명령에서 `--port`만 블루투스 포트로 바꿉니다(my는 `COM11`).
```powershell
.\run.bat --port COM11 --role P1 --listen --allow-from P2주소
```

**통과 기준**: 「5」와 같습니다. 그리고
- 차가 달리다가 끊기듯 멈칫하지 않는지 봅니다. 자주 멈칫하면 차의 시간 제한(0.3초)을 늘릴지 sunbell과 정합니다.
- P1을 끌 때 `--port`가 블루투스여도 차가 바로 서는지 봅니다.

**지난 결과**: 아직 하지 않았습니다. 11/11 학과 발표회 때 my와 메인 차는 블루투스(`COM11`)로 글자를 주고받았습니다(협동 레이싱 이전 코드).

## 7 · 트랙 리허설

**무엇을 보나**: 실제 트랙 위에서 한 판(약 3분)을 끝까지 할 수 있는지. 맵을 다시 정하는 중이라 자세한 순서는 맵이 정해지면 채웁니다.

**지금 정해진 것**(팀 결정 기록 11/20): 장애물은 넣지 않습니다. 벽에 닿아도 그대로 계속합니다. 차는 강의실 바닥에서 달립니다.

**볼 것 (Claude 제안, 맵이 정해지면 다듬음)**
- 고른 커브 짝으로 트랙의 굽은 길을 돌 수 있는지. 강의실 바닥은 시험한 바닥과 달라 값을 다시 맞춰야 할 수 있습니다(짐작). 강의실은 11/27부터 쓸 수 있습니다.
- 한 판을 몇 번 연달아 해도 AA 건전지가 버티는지.
- 초음파 센서가 벽(약 5 cm 높이)을 보고 서는지, 벽 앞에서 뒤로 빠질 수 있는지.
- 예비 차로 바꿔도 같은 노트북 명령으로 바로 이어지는지(블루투스 포트 번호만 바뀜).

## 9 · 낱말 풀이

| 말 | 뜻 |
|---|---|
| P1 / P2 | 협동 레이싱의 두 역할. P1은 앞뒤(두 팔 들기 `W`, T자 `S`), P2는 좌우(왼팔 `A`, 오른팔 `D`) |
| 멈춤 글자 | 팔을 내릴 때 보내는 글자. `X` = 앞뒤만 끔, `Z` = 좌우만 끔. 3번 연달아 보냅니다 |
| 시간 제한 | 차가 0.3초 동안 글자를 못 받으면 그 입력을 스스로 끄는 것. 연결이 끊겨도 차가 섭니다 |
| 커브 짝 | 휘며 갈 때 바깥 바퀴와 안쪽 바퀴의 속도 짝. 안쪽이 느릴수록 좁게 돕니다 |
| `-Plan` | 시험 스크립트에 주는 「글자:누르는 시간(ms)」 목록. `W+A`는 두 글자를 동시에 누른 것 |
| `ipconfig` | 윈도우에서 이 노트북의 와이파이 주소를 보는 명령 |
| UDP | 같은 와이파이의 두 노트북이 짧은 글자를 빠르게 주고받는 방법. 가끔 한 글자가 사라질 수 있습니다 |
| 나가는(Outgoing) 포트 | 노트북이 블루투스로 글자를 보낼 때 여는 COM 포트 |
