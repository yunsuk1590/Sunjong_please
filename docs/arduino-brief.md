## 2. 지금 상황 (2026-11-05)

  - 두 가지를 따로 만들지, 하나만 만들지, 한 게임으로 엮을지는 정하지 않았습니다(안건 「운영 2 · 최종 콘텐츠」). 세부 동작과 규칙도 정하지 않았습니다.
- **키트**: 에듀이노 「2휠 교육용 RC카」 2대. sunbell과 yunsuk1590이 1대씩 갖고 있습니다.
  - 팀이 함께 조립했고, 앞뒤로 움직이는 예제와 **스마트폰 앱으로 블루투스 조종**까지 해 봤습니다.
  - 블루투스 모듈은 HC-06입니다.
- **이음제**: 2026년 11월 28일(토). 세부 일정은 아직 정하지 않았습니다(안건 「운영 5 · 이음제 날짜와 일정」).

## 3. 첫 할 일 (순서대로)

콘텐츠가 어떻게 정해지든 필요한 일부터 합니다. 하나가 끝날 때마다 `arduino/README.md`에 결과를 적고 sunbell에게 알려 주세요.

### 첫 할 일 ① 맥에 아두이노 프로그램 설치하고 업로드 확인하기
- 아래 「4. 필요한 환경」대로 설치합니다.
- 직접 쓴 짧은 프로그램(예: 모터를 2초 돌리기)을 키트 보드에 올려 봅니다.
- **됐다고 볼 때**: 맥에서 업로드가 되고, 차가 프로그램대로 움직입니다.

### 첫 할 일 ② 맥에서 블루투스로 명령을 보내 차 움직이기 (가장 중요)
- 지금까지는 스마트폰 앱으로 조종했습니다. 이번에는 **맥이 보낸 글자**로 차가 앞으로 가고 멈추게 합니다. 나중에 몸 동작 인식 결과도 노트북에서 이렇게 보내게 되므로, 이 시험이 그 첫걸음입니다.
- 방법(예)
  1. 맥의 「시스템 설정 → Bluetooth」에서 HC-06과 짝을 맺습니다(페어링).
  2. 아두이노 프로그램의 포트 목록에서 `/dev/cu.HC-06…` 같은 이름을 고릅니다.
  3. 시리얼 모니터 창에서 글자를 보냅니다.
- 명령 글자는 **임시로 자유롭게** 정해도 됩니다. 최종 약속은 안건 「개발 2 · 내보낼 값」에서 정합니다. 그래서 코드에서 **글자를 해석하는 부분을 한곳에 모아** 두면 나중에 바꾸기 쉽습니다.
- **됐다고 볼 때**: 맥에서 보낸 글자로 차가 앞으로 가고 멈춥니다.
- **함께 적어 줄 것**
  - 글자를 보낸 뒤 차가 바로 반응하는지(느낌으로)
  - 몇 m 떨어져도 되는지
  - 연결이 중간에 끊기지 않는지
  - 이 결과로 안건 「개발 3 · 아두이노 연결 방식」(블루투스로 할지 USB 선으로 할지)을 정합니다.
- **안 되면**: 오류 메시지와 해 본 것을 적어 sunbell에게 알려 주세요. 맥에서 HC-06 포트가 잘 안 열렸다는 사례가 있습니다(「8. 막히면」의 참고 자료). 다른 방법은 윈도우 PC에서 시험해 보기, 또는 USB 선으로 직접 연결해 보기입니다.

### 첫 할 일 ③ 속도 단계 만들기
- 첫 할 일 ②와 같은 방식(글자 명령)으로 **천천히 / 보통 / 빠르게** 같은 속도 단계를 만듭니다.
- 쓰이는 곳: 「타이밍 주행」에서 동작에 성공하면 빠르게, 실패하면 천천히 가거나 멈추는 데 쓸 수 있습니다.
- **생각해 둘 것 (Claude 의견, 아직 정하지 않음)**: 연결이 끊기거나 명령이 한동안 안 오면 차가 **스스로 멈추게** 할지. 부스에서 차가 혼자 계속 달려 나가는 사고를 막을 수 있습니다.

### 첫 할 일 ④ 차단봉에 쓸 부품 조사하기 (조사만, 사지 않기)
「동작 게이트」를 만들게 될 때를 대비해 아래를 확인하고 `arduino/README.md`에 적어 주세요. **부품을 사기 전에는 sunbell과 상의**합니다.
- 차단봉을 올리고 내릴 **서보모터**가 있는지, 몇 개인지, 모델명
- 차에 쓰지 않는 **아두이노 보드**가 남는지. 차단봉은 트랙에 따로 놓이므로, 차에 달린 보드와 다른 보드가 필요할 수 있습니다.
- 차단봉 보드를 노트북과 어떻게 이을 수 있는지(USB 선, 또는 남는 블루투스 모듈)
- 더 사야 할 것이 있다면 그 목록

## 5. 몸 동작 인식 쪽과 만나는 지점 (아직 정하지 않음)

전체 흐름은 이렇습니다.

```
웹캠 → [몸 동작 인식] → [값 만들기] → [통합: 아두이노로 보내기] → [아두이노: 받아서 움직이기]
        sunbell          sunbell         담당 아직 정하지 않음          yunsuk1590
```

- **아직 정하지 않은 것**
  - 노트북이 아두이노에 보낼 **값의 모양** → 안건 「개발 2 · 내보낼 값」
    - 후보: 명령어 방식(예: 「앞으로」 「멈춤」) / 숫자 방식(예: 속도 0~1) / 둘을 섞은 방식
  - 노트북과 아두이노를 **어떻게 이을지** → 안건 「개발 3 · 아두이노 연결 방식」
    - 후보: 블루투스(HC-06) / USB 선
  - 정해지면 「값 약속 문서」(`docs/value-spec.md`)로 정리합니다.
- **그 전까지 아두이노 쪽이 해 둘 것**
  - 글자를 해석하는 코드를 한곳에 모아 두기(첫 할 일 ②)
  - 맥에서 HC-06이 되는지와 반응 느낌을 알려 주기(첫 할 일 ②의 결과)
- 몸 동작 인식 쪽은 「첫 번째 목표」(동작을 제대로 알아보는지 확인)가 끝난 뒤에 값을 내보내는 부분을 만듭니다. 이 순서는 이미 정해져 있습니다.

## 6. 브랜치와 커밋

### 처음 한 번: 내 브랜치 만들기 (맥의 「터미널」 앱에서)
팀 문서를 main에 합치는 PR(sunbell이 만듦)이 합쳐진 뒤에 합니다.

```
git clone https://github.com/yunsuk1590/Sunjong_please.git
cd Sunjong_please
git switch main
git pull
git switch -c yunsuk1590/arduino
git push -u origin yunsuk1590/arduino
```

- 각 줄이 하는 일: 레포 받기 → 그 폴더로 들어가기 → main으로 가기 → main 최신으로 받기 → 내 브랜치 `yunsuk1590/arduino` 만들기 → 그 브랜치를 깃허브에도 만들기
- 레포를 이미 받아 두었다면 첫 줄은 건너뛰고, 그 폴더에서 `git fetch`를 먼저 합니다.
- 이 맥에서 처음 커밋한다면, 커밋에 남을 이름을 먼저 정합니다.
  - `git config --global user.name "깃허브 아이디"`
  - `git config --global user.email "깃허브에 등록한 이메일"`

### 폴더 구성 (예시)

```
arduino/
  README.md          작업 기록: 설치한 버전, 보드 설정, 시험 결과, 정한 것
  car/car.ino        차: 명령을 받아 움직이기
  gate/gate.ino      차단봉: 만들기로 정해지면
```

아두이노 프로그램은 **프로그램 파일 이름과 폴더 이름이 같아야** 합니다(예: `car` 폴더 안의 `car.ino`).

### 작업을 올릴 때

```
git add arduino
git commit -m "arduino - 무엇을 바꿨는지"
git push
```

### main에 합칠 때
- 한 덩어리가 끝나면(예: 「맥에서 보낸 글자로 차가 움직임」) 깃허브에서 `yunsuk1590/arduino` → `main` PR을 엽니다.
- sunbell이 검토한 뒤 **「Create a merge commit」**(기본 합치기)으로 합칩니다.
- 합친 뒤에도 `yunsuk1590/arduino` 브랜치는 지우지 않습니다. 계속 그 브랜치에서 작업합니다.

## 7. 지켜 줄 것

- **레포에는 직접 새로 쓴 코드만** 올립니다. 에듀이노 예제 코드(그대로든 고친 것이든), 키트 교육 자료, 라이브러리·드라이버 파일은 올리지 않습니다. 예제는 보고 배우는 데만 씁니다. (이유: [팀 결정 기록](team-decisions.md)의 「키트 교육 자료와 코드 규칙」)
- **main에 직접 올리지 않습니다.** 내 브랜치에서 작업하고 PR로 합칩니다.
- **고치지 않는 것**: 다른 사람의 브랜치(`sunbell/…`), 몸 동작 인식 코드(`motion/` 폴더), 원래 있던 프로그램(`Main.py` 등), 팀 문서(`team-`로 시작하는 문서). 바꿀 것이 있으면 sunbell에게 알려 주세요.
- 무언가를 정하면 `arduino/README.md`에 **날짜, 내용, 이유, 정한 사람**을 적습니다.
- 직접 확인한 것과 짐작을 구분해서 적습니다. AI에게 받은 분석에는 「Claude 분석」처럼 표시합니다.
- 레포가 공개라서 연락처 같은 개인정보는 적지 않습니다.
