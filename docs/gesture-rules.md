# 동작 판정 기준

몸 동작 인식 프로그램(`motion` 폴더)이 **어떤 동작을, 무엇을 보고, 어떤 기준으로** 판정하는지 적은 문서입니다.

- **판정 기준의 원본은 이 문서**입니다. 기준(숫자, 규칙)을 바꾸면 코드와 이 문서를 같이 고칩니다.
- 그렇게 정한 **이유**는 `docs/decisions.md`에 적습니다.
- 「상태」 칸의 뜻
  - **확정**: 정한 사람이 화면으로 확인하고 정한 것
  - **시작값**: 일단 넣어 둔 값이라 화면을 보며 조정할 것
- 「정한 사람」은 sunbell / 교수님 / 팀으로 구분합니다.

## 동작 목록

| 동작 | 화면에 나오는 이름 | 판정 코드 | 상태 |
|---|---|---|---|
| 두 팔 들기 | `ARMS_UP` | `motion/gestures/arms_up.py` | 판정 방법 확정, 숫자는 시작값 |
| 몸 좌우 기울이기 | `LEAN_LEFT` / `LEAN_RIGHT` | `motion/gestures/lean.py` | 판정 방법 확정, 켜짐 각도 확정(22도), 꺼짐 각도는 시작값. 몸통 기울기를 쓸지는 팀과 의논할 것 |

두 동작은 3단계 **확인용 샘플**입니다. 최종 콘텐츠의 동작은 아직 정하지 않았습니다.

## 모든 동작에 공통인 기준

| 항목 | 기준 | 상태 · 정한 사람 |
|---|---|---|
| 왼쪽·오른쪽 | **체험자 본인 기준**. 화면을 거울처럼 보여 주므로 화면 왼쪽이 곧 체험자의 왼쪽이다. MediaPipe의 LEFT/RIGHT 이름은 거울 화면에서 뒤바뀌므로 쓰지 않고, 화면에 보이는 위치로 정한다 | 확정 · sunbell(9/29 계획 승인) |
| 관절이 "보인다" | MediaPipe가 준 보이는 정도(visibility)가 **0.5 이상**이고 화면 안에 있을 때만 판정에 쓴다 | 시작값 · 구글 기본값을 따름 |
| 사람이 있다 | MediaPipe가 사람이라고 확신하는 정도가 0.5 이상(구글 기본값) | 시작값 |
| 사람이 없을 때 | 사람이 **0.5초** 넘게 안 보이면 모든 동작이 꺼진다(화면은 `NONE`). 더 짧게 안 보이면(사진 몇 장 놓침) 결과를 그대로 유지한다 | 끄는 것은 확정 · sunbell(계획 승인). 0.5초도 **확정** · sunbell(11/5 화면 확인: 화면 밖으로 완전히 나가면 바로 `NONE`). 부스 리허설 때 다시 확인 |
| 거리·각도 재는 법 | 관절 위치를 **픽셀**로 바꿔서 잰다. 화면 비율(4:3, 16:9)이 달라도 각도가 같게 나온다 | 확정(기술 선택) |
| 동작끼리 | 서로 다른 동작은 **동시에 켜질 수 있다**(예: `ARMS_UP + LEAN_LEFT`). 한 동작 안의 상태는 하나만 켜진다(왼쪽·오른쪽 기울이기가 동시에 켜지지 않음) | 확정 · sunbell(계획 승인, 10/4 화면 확인: "팔 든 상태에서 기울이기 정도는 괜찮음"). 동작이 늘어나면 다시 본다 |
| 깜빡임 막기 ① 기준 | **켜지는 기준과 꺼지는 기준을 다르게** 둔다. 이미 켜진 동작은 조금 더 너그럽게 봐서, 경계에서 켜졌다 꺼졌다 하지 않게 한다 | 확정 · sunbell(계획 승인) |
| 깜빡임 막기 ② 시간 | 결과가 일정 시간 이어져야 바뀌게 한다(떨림 방지, `motion/stabilizer.py`). 두 팔 들기: 0.25초 유지되면 켜짐 / 0.35초 사라지면 꺼짐. 기울이기: 0.20초 / 0.25초. 왼쪽에서 오른쪽으로 바로 바뀔 때는 켜짐 시간을 쓴다. 기다리는 만큼 반응이 늦어진다 | **확정** · sunbell(11/5 화면 확인: 굼뜨지 않음, 바뀐 횟수 RAW 22·24번 → STABLE 6·6번). 부스 리허설 때 다시 확인. 처음 시작값은 0.15/0.25초, 0.10/0.15초(`config.py`의 `arms_on` 등, 실행할 때 `--arms-on` 등으로 바꿔 볼 수 있음) |
| 판정하는 사람 | 지금은 **첫 번째로 찾은 한 사람**만 판정한다. 여러 명은 "동시 4인"의 뜻이 정해진 뒤에 정한다 | 확정(지금 단계) |
| 기억하는 시간 | 최근 **2초** 동안의 관절 위치를 기억한다. 제자리 달리기 같은 반복 동작을 나중에 판정할 때 쓴다 | 시작값 |

## 두 팔 들기 (`ARMS_UP`)

**체험자가 하는 동작**: 두 팔을 머리 위로 든다.

**판정 순서** (팔 하나씩)
1. 손목이 잘 보이고 화면 안에 있으면 **손목**으로 본다.
2. 손목이 화면 밖이거나 잘 안 보이면 **팔꿈치**로 대신 본다.
3. 손목도 팔꿈치도 안 보이면 그 팔은 "안 들림"으로 본다.

두 팔이 **모두** 들렸으면 `ARMS_UP`이다. 한 팔만 들면 켜지지 않는다.

| | 켜지는 조건(꺼져 있을 때) | 꺼지는 조건(켜져 있을 때) |
|---|---|---|
| 손목으로 볼 때 | 손목이 **코보다 위** | 손목이 **어깨 아래**로 내려감 |
| 팔꿈치로 볼 때 | 팔꿈치가 어깨보다 **어깨너비 × 0.15** 이상 위 | 팔꿈치가 **어깨 아래**로 내려감 |
| 코가 안 보일 때 | 코 대신 "두 어깨 가운데보다 어깨너비 × 0.5 위"를 머리 높이로 본다 | |
| 어깨가 안 보일 때 | 판정하지 않는다(꺼짐) | |

| 숫자 | 값 | 코드 위치 | 상태 |
|---|---|---|---|
| 팔꿈치 여유 | 어깨너비 × 0.15 | `arms_up.py`의 `ELBOW_MARGIN` | 시작값 |
| 코 대신 쓰는 머리 높이 | 어깨너비 × 0.5 위 | `arms_up.py` | 시작값 |

**화면에서 확인하는 법**: `ARMS:` 줄에 팔마다 무엇으로 판정했는지 나온다(`L`은 화면 왼쪽 팔). 예: `ARMS: L wrist UP  R elbow UP`.

**정한 사람**: 판정 방법(손목 또는 팔꿈치)은 sunbell(10/4) 확정.

**이유**: 가까이 서면 손목이 화면 밖으로 나가고, 그때 MediaPipe가 추측한 손목 위치가 심하게 흔들렸다(10/4 2단계 시험, 1 m 안쪽). 자세한 이유는 `decisions.md`를 본다.

**알려진 한계**
- 팔을 옆으로 수평하게 드는 자세(T자)는 켜지지 않는다. 손목이 코보다 낮기 때문이다.
- 한 팔만 들면 켜지지 않는다. 의도한 동작이다.

## 몸 좌우 기울이기 (`LEAN_LEFT` / `LEAN_RIGHT`)

**체험자가 하는 동작**: 서서 상체를 왼쪽 또는 오른쪽으로 기울인다.

**재는 것**: **어깨 기울기**. 두 어깨를 잇는 선이 수평에서 기운 각도(도)이다.
- 체험자 왼쪽(화면 왼쪽) 어깨가 내려가면 **+**, 오른쪽 어깨가 내려가면 **−**.
- 두 어깨가 잘 보여야 잴 수 있다.

| | 켜지는 조건 | 꺼지는 조건 |
|---|---|---|
| `LEAN_LEFT` | 어깨 기울기 **+22도 이상** | 켜진 뒤 **+7도 아래**로 돌아옴 |
| `LEAN_RIGHT` | 어깨 기울기 **−22도 이하** | 켜진 뒤 **−7도 위**로 돌아옴 |

| 숫자 | 값 | 코드 위치 | 상태 |
|---|---|---|---|
| 켜짐 각도 | **22도** | `config.py`의 `lean_enter`(실행할 때 `--lean-enter`로 바꿔 볼 수 있음) | **확정** · sunbell(10/4). 12도 → 15·20·25도 시험 → 22도. 25도는 일부러 기울일 때 빡빡했다 |
| 꺼짐 각도 | 7도 | `config.py`의 `lean_exit`(`--lean-exit`) | 시작값. 켜짐 각도와 사이가 넓어서, 한 번 켜지면 거의 바로 서야 꺼진다 |

**비교용 숫자: 몸통 기울기**
- 엉덩이 가운데 → 어깨 가운데를 잇는 선이 수직에서 기운 각도다. 엉덩이가 화면에 보일 때만 나온다.
- **판정에는 쓰지 않고** 화면 `LEAN:` 줄에만 보여 준다(`torso`).
- 판정에 쓸지는 팀과 의논한다. 아래 「검토한 대안」과 `docs/team-agenda.md` 개발 1을 본다.

**화면에서 확인하는 법**
- 맨 아래 막대의 점이 지금 어깨 기울기다. 체험자가 왼쪽으로 기울면 점이 왼쪽으로 간다.
- 노란 선은 켜짐 기준, 회색 선은 꺼짐 기준이다. 켜지면 점이 초록색이 된다.
- `LEAN:` 줄에 어깨와 몸통 각도가 숫자로 나온다.

**정한 사람**: 판정 방법(어깨로 판정 + 몸통 숫자 표시)과 켜짐 각도 22도는 sunbell(10/4) 확정.

**알려진 위험(10/4 sunbell 확인)**
- 한 팔을 끝까지 쭉 펴면 그쪽 어깨가 올라간다. 그래서 반대쪽 기울이기가 잘못 켜졌다. 예: 오른팔을 쭉 펴면 오른쪽 어깨가 올라가 `LEAN_LEFT`가 뜸. 12도일 때 일어났다.
- 카메라 각도와 거리, 서는 방향에 따라 같은 동작도 어깨 각도가 다르게 나온다. 그래서 기준을 보수적으로 22도까지 올렸다.
- 기준을 높이면 잘못 켜짐이 줄 뿐 완전히 없어지지는 않는다. 또 일부러 기울일 때 빡빡해진다(25도는 빡빡했음).

**검토한 대안: 몸통 기울기로 판정하기** (자세한 비교는 `docs/team-agenda.md` 개발 1, 팀과 의논할 것)

| 방법 | 어떻게 | 장점 | 단점 |
|---|---|---|---|
| ① 어깨 유지 + 기준 높이기(**지금**) | 어깨 기울기 22도 | 가장 간단. 가까이 서도 됨 | 잘못 켜짐이 완전히 사라지진 않음. 빡빡해질 수 있음 |
| ② 몸통 우선, 안 보이면 어깨로 대신 | 엉덩이가 보이면 몸통 기울기로, 안 보이면 어깨(높은 기준)로 판정 | 한 팔 쭉 펴기와 비스듬히 서기에 강함. 가까이서도 동작함 | 규칙이 조금 복잡함. 몸통용 기준 각도를 새로 정해야 함 |
| ③ 둘 다 같은 방향으로 기울 때만 | 어깨와 몸통이 모두 기준을 넘어야 켜짐 | 잘못 켜짐이 가장 적음 | 엉덩이가 꼭 보여야 함. 가장 엄격함 |

## 새 동작을 추가할 때

1. 코드를 추가한다(`motion/README.md`의 "새 동작 추가하는 방법").
2. 이 문서에 같은 형식으로 한 칸을 추가한다: 체험자가 하는 동작, 판정 순서, 켜짐·꺼짐 조건, 숫자와 코드 위치, 화면에서 확인하는 법, 정한 사람, 알려진 한계.
3. 「바뀐 기록」에 한 줄을 추가한다.
