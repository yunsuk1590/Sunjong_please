# 협동 레이싱 차 코드 (car_race)

> **이 문서는?** 이음제에서 할 콘텐츠 「협동 레이싱」에 쓰는, **W/A/S/D 글자로 조종하는 차 코드**와 지금까지의 시험 결과를 정리한 **인계 문서**입니다. 이 문서만 읽고 차에 올려 이어서 시험할 수 있게 썼습니다.
> - **누가 읽나요?** 아두이노 담당 yunsuk1590. 팀장 sunbell.
> - **작성**: 2026-11-19, sunbell(Claude 도움). 이 날짜까지의 시험 결과입니다.
> - **어디에 있나요?** 이 레포의 `sunbell/arduino` 브랜치, `arduino/car_race/`입니다. `main`과 `yunsuk1590/arduino`는 고치지 않았습니다.
> - **초음파로 멈추기만 하는 코드**는 같은 브랜치의 `arduino/car_ultrasonic/`입니다. 이 코드는 그 초음파 부분을 가져와 썼습니다.
> - 처음 보는 말은 맨 아래 「10 · 낱말 풀이」에 있습니다.

## 1 · 무엇을 만들었나

- 노트북이 보낸 글자로 차를 **컨트롤러처럼** 조종합니다. 노트북이 동작을 인식하는 동안 같은 글자를 0.15초마다 계속 보내고, 차는 글자가 **0.3초 안에 안 오면 그 입력을 끕니다.** 그래서 노트북이 멈추거나 연결이 끊기면 차가 스스로 섭니다.
- 앞뒤(`W`/`S`)와 좌우(`A`/`D`)를 **따로 기억해서 합칩니다.** 그래서 앞으로 가면서 왼쪽으로 휘는 것(`W`+`A`)도 됩니다.
- 앞으로 갈 때만 **초음파 센서**로 벽 앞(20 cm)에서 막습니다. 뒤로 가기와 제자리 돌기는 막지 않아서, 벽에 붙어도 빠져나올 수 있습니다.
- 블루투스(HC-06)와 USB 선, 두 곳에서 같은 글자를 받습니다.
- 키트 예제 코드는 옮기지 않고 새로 썼습니다. 배선만 키트 자료에서 확인했습니다.

## 2 · 글자의 뜻

| 글자 | 뜻 | 상태 |
|---|---|---|
| `W` | 앞으로 | 2026-11-19 sunbell 결정(화이트보드의 조작) |
| `S` | 뒤로 | 2026-11-19 sunbell 결정 |
| `A` | 왼쪽 | 2026-11-19 sunbell 결정 |
| `D` | 오른쪽 | 2026-11-19 sunbell 결정 |
| `X` | **앞뒤 입력만** 끔(`W`/`S`를 멈춤) | 2026-11-20 sunbell 결정. 앞뒤를 맡은 노트북(P1)이 팔을 내릴 때 보냅니다 |
| `Z` | **좌우 입력만** 끔(`A`/`D`를 멈춤) | 2026-11-20 sunbell 결정. 좌우를 맡은 노트북(P2)이 팔을 내릴 때 보냅니다 |

- 한 사람이 멈춰도 다른 사람의 입력은 끊기지 않게 하려고 나눴습니다. **둘 다 끄려면 `X`와 `Z`를 이어서 보냅니다**(2026-11-20 sunbell 결정. 새 글자는 만들지 않았고, 차 코드는 더 고칠 것이 없습니다). 노트북 쪽은 P1이 팔을 내릴 때 `X`, P2가 팔을 내릴 때 `Z`, 둘 다 끌 때 `X`와 `Z`를 이어서 보내도록 MediaPipe 세션이 맞춥니다.
- **노트북이 멈춤 글자를 3번 연달아 보내도 됩니다**(2026-11-20, 노트북 프로그램 `sunbell/motion` 5a2e375). 처음 바로, 나머지 둘은 0.15초 간격입니다. 차는 `X`와 `Z`를 글자마다 따로, 몇 번 오든 같게 처리합니다. 이미 꺼진 축에 다시 와도 아무 일도 없습니다. 같은 축을 그 사이에 다시 켜면 노트북이 남은 멈춤 글자를 보내지 않습니다. 둘 다 끌 때는 `XZ`(두 글자 이어서)가 옵니다. 앞뒤 입력에서 좌우 입력으로 바로 바꿀 때는 앞의 멈춤 글자와 새 글자가 함께 옵니다(예: `X`+`A`). 이 두 가지도 차는 이상 없이 받았습니다(「11 · 진행 기록」 11/20).
- 글자가 0.3초 안에 안 오면 그 입력이 저절로 꺼지므로, `X`와 `Z`가 한 번 안 와도 차는 곧 섭니다. 시간 제한은 0.3초 그대로입니다(2026-11-20 sunbell 결정).

- **대문자만** 알아듣습니다. 소문자와 줄바꿈(`\r`, `\n`)은 무시합니다.
- **주의:** 예전 코드(`car.ino`, `car_backup`)에서는 `S`가 「멈춤」이었습니다. 이 코드에서 `S`는 **뒤로 가기**입니다.
- 글자는 어느 쪽(USB, 블루투스)에서 왔는지와 상관없이 **같은 뜻**입니다. 그래서 노트북 1대로도 2대로도 코드는 같습니다.
- 글자를 바꾸려면 `car_race.ino` 맨 위의 「글자 약속」만 고칩니다.

## 3 · 차에 올리는 방법

| 항목 | 내용 |
|---|---|
| 아두이노 프로그램 | Arduino IDE 2.3.10 (터미널에서는 IDE 안의 `arduino-cli`) |
| 보드 설정 | Arduino AVR Boards 1.8.8, 보드 「Arduino Uno」(`arduino:avr:uno`) |
| 라이브러리 | **Adafruit Motor Shield library 1.0.1**(V1, 코드에서는 `AFMotor`). 각자 설치하고 레포에는 넣지 않습니다 |
| 올릴 파일 | `arduino/car_race/car_race.ino` |

1. IDE에서 `car_race.ino`를 열고 보드를 「Arduino Uno」, 포트를 차 보드의 USB 포트로 고른 뒤 올립니다. 컴파일 결과는 프로그램 7,058바이트(21%), 전역 변수 약 350바이트(17%)입니다.
2. 올릴 때 **블루투스 모듈이 USB와 같은 선(D0, D1)에 꽂혀 있지 않은지** 봅니다. 이 차 코드는 모듈을 A5/A4에 꽂으므로 그대로 올려도 됩니다.
3. 올린 뒤 시리얼 모니터(9600)에 「car_race 시작: 멈춤 상태. W 앞, S 뒤, A 왼, D 오른, X 앞뒤 끔, Z 좌우 끔」이 나오면 됩니다.

## 4 · 배선 (키트 차 기준)

| 부품 | 핀 | 확인 |
|---|---|---|
| 왼쪽 바퀴 | 모터 쉴드 M1 | 2026-11-11 sunbell 차 |
| 오른쪽 바퀴 | 모터 쉴드 M4 | 2026-11-11 sunbell 차 |
| 블루투스(HC-06) | 받기 A5, 보내기 A4 | 2026-11-11 sunbell 차 |
| 초음파 센서 | trig A0, echo A1 | 2026-11-17 sunbell 차(키트 자료와 같음) |

- 바퀴가 거꾸로 돌면 `car_race.ino`의 `LEFT_FORWARD_DIR`, `RIGHT_FORWARD_DIR`에서 그 바퀴 값만 `FORWARD` ↔ `BACKWARD`로 바꿉니다. sunbell 차는 지금 값이 맞습니다.
- 차에는 **블루투스 모듈을 1개만** 답니다(2026-11-19 sunbell 결정). 두 번째 모듈을 달 납땜된 구멍이 없고, 지금은 납땜할 수 없기 때문입니다. 노트북 2대의 글자는 한 프로그램이 모아서 이 모듈 하나로 보냅니다(노트북 쪽 일).

## 6 · 아직 시험하지 않은 것

- `W`+`A` 안쪽 150의 커브, `W`+`D`(오른쪽 커브)의 모양과, 왼쪽과 오른쪽이 같은 정도로 휘는지.
- **블루투스로** 같은 시험(USB 선 없이 달리기). 지금까지는 USB로만 했습니다.
- **초음파로 앞이 막히는 것을 바닥에서 직접**(`car_race`에서). 막힘이 로그에 나오는 것은 봤고, 앞으로 가다가 서는 것은 `car_ultrasonic`에서 11/17에 시험했습니다(AA 건전지, 255에서 20 cm 기준으로 약 14 cm에서 섬).
- 벽에 붙은 상태에서 뒤로 빠지는 것(`S`).
- 노트북 2대의 글자가 한 모듈로 섞여 들어올 때의 동작.
- 18650 충전지(약 7.4V)로 바꿨을 때. 속도, 휘는 정도, 멈추는 거리가 달라질 수 있어 값을 다시 맞춰야 합니다.
- 트랙 위에서 오래 달리는 것(건전지가 약해질 때).

## 7 · 다음 시험 순서

1. **커브 모양 고르기:** 아래 「8 · USB로 시험하는 법」의 커브 짝 `1`~`6`을 바꿔 가며 `W+A`, `W+D`를 시험하고, 마음에 드는 번호를 `CURVE_DEFAULT`에 적어 올립니다. 왼쪽과 오른쪽이 비슷하게 도는지도 봅니다(두 바퀴 힘 차이는 오른쪽 94% 보정으로 이미 맞춰져 있어서 같은 짝이면 좌우가 같아야 합니다. 2026-11-20 Claude 분석).
2. **블루투스 시험:** 차의 블루투스 모듈(이 차는 `IEUMCAR2`)을 윈도우에서 짝 맺고 「나가는」 포트로 같은 글자를 보냅니다. USB 선은 뽑고 차를 달려 봅니다.
3. **초음파:** 앞 40 cm쯤에 평평한 물건을 세우고 `W`를 계속 보내서 20 cm쯤에서 서는지 봅니다. 서 있는 동안 `S`로 뒤로 빠지는지, `A`로 도는지 봅니다.
4. **동시에 놓을 때의 움찔:** `W`와 `A`를 동시에 놓는 시험을 여러 번 하고 눈으로 확인합니다. 눈에 띄면 「앞뒤 입력이 끝난 뒤 돌기만 남을 때 돌기를 약 0.1초 늦게 시작」하게 고치는 것을 제안합니다.
5. 노트북 쪽(MediaPipe) 프로그램과 연결해서 팔 동작으로 달려 봅니다.

## 8 · USB로 시험하는 법

- `arduino/car_race/tools/send_keys.ps1`이 글자를 컨트롤러처럼 반복해서 보내고, 차의 로그를 시간과 함께 보여 줍니다.

```powershell
powershell -ExecutionPolicy Bypass -File arduino/car_race/tools/send_keys.ps1 -Port COM5 -Plan "W:1000;W+A:1500;A:500;S:800"
```

- 포트(`COM5`)는 각자 차 보드의 USB 포트로 바꿉니다. 포트를 열면 보드가 다시 켜지고 약 2.5초 뒤에 시작합니다.
- **차를 바닥에 놓고 앞뒤 약 1 m를 비웁니다.** 앞 20 cm 안에 물건이 있으면 앞으로 가지 않습니다. USB 선이 당기지 않게 여유를 줍니다.
- 시리얼 모니터는 닫고 씁니다(COM 포트는 한 번에 한 프로그램만 열 수 있습니다).
- 시리얼 모니터에서 글자를 한 번 보내면 0.3초만 가고 서므로, 컨트롤러 같은 시험은 이 스크립트로 합니다.

**커브 모양을 차를 다시 안 올리고 바꿔 보는 법 (2026-11-20 추가)**
- 글자 `1`~`6`을 보내면 커브 짝이 바뀌고, 차가 「커브 3: 바깥 255 / 안쪽 110」처럼 알려 줍니다. 켜졌을 때는 `CURVE_DEFAULT`(지금 `2`)입니다.

| 글자 | 바깥 / 안쪽 | 뜻 |
|---|---|---|
| `1` | 255 / 190 | 넓게. 2026-11-19에 거의 직진이었음 |
| `2` | 255 / 150 | 지금 기본값 |
| `3` | 255 / 110 | 더 좁게 |
| `4` | 255 / 70 | 더 좁게 |
| `5` | 200 / 95 | 바깥도 약하게(앞 힘을 줄이고 좌우 차이는 비슷하게 유지). sunbell 아이디어를 옮긴 것 |
| `6` | 255 / 0 | 안쪽 바퀴를 놓음. 가장 좁게 |

```powershell
powershell -ExecutionPolicy Bypass -File arduino/car_race/tools/send_keys.ps1 -Port COM5 -Plan "3:200;W+A:1500;W+D:1500;S:800"
```

- 위 명령은 먼저 `3`번 짝을 고르고 `W+A`, `W+D`를 시험합니다. 포트를 열 때마다 보드가 다시 켜져서 번호는 기본값(`CURVE_DEFAULT`)으로 돌아가므로, **시험 한 번마다 첫 단계에 번호를 넣습니다.**
- 안쪽 속도가 낮으면(예: 70 이하) AA 건전지에서 안쪽 바퀴가 아예 안 돌 수 있습니다(11/11에 200도 못 출발한 기록, 짐작).

**자주 쓰는 시험 모음 (2026-11-20 추가)**
- 아래 `-Plan` 문자열을 복사해서 `-Plan "..."` 자리에 넣습니다. 포트는 각자 바꿉니다. **모든 시험은 차를 바닥에 놓고 앞뒤 1 m를 비운 뒤** 합니다.
- 「로그에서 볼 값」은 sunbell의 차(AA 건전지, 2026-11-20)에서 나온 값입니다. 앞 약 0.15초는 출발 순간 밀기(255)라서 첫 값이 더 큽니다.

| 무엇을 보나 | `-Plan` | 로그에서 볼 값 / 눈으로 볼 것 |
|---|---|---|
| 직진·후진 | `W:1000;S:800` | `바퀴 왼 255 오 239`, 뒤로는 `-255 / -239`. 한쪽으로 휘는지 봅니다 |
| 제자리 돌기 | `A:500;D:500` | `왼 -190 오 178`(왼쪽), 반대는 부호가 반대. 얼마나 도는지 봅니다 |
| 커브 번호 고르기 | `3:200;W+A:1500;W+D:1500` | 번호(`3`)를 바꿔 가며 시험. 왼쪽과 오른쪽이 같게 도는지 봅니다. 번호는 위 표 |
| 시간 제한(0.3초) | `W:600` | 글자를 끊은 뒤 약 0.2~0.3초 만에 `바퀴 왼 0 오 0` |
| 멈춤 글자 `X`/`Z` (서 있을 때) | `W:600;X:450;W:600;X+Z:450;A:500;Z:450;S:400;X:450` | `X`나 `Z`가 3번 와도 이상 없고, 멈춘 뒤 `W`가 다시 출발. 노트북이 보내는 방식(3번 연달아) |
| 멈춤 글자 `X`/`Z` (가는 도중) | `W:600;X:450;A:500;Z:450;W:500;A+X:450;A:300;Z:450;Q:600` 과 `-GapMs 0` | 첫 `X`/`Z` 뒤 약 15 ms 만에 `바퀴 0 0`. `A+X`는 직진이 끊기고 제자리 돌기만 남음. 명령 끝에 ` -GapMs 0`을 붙입니다 |

```powershell
powershell -ExecutionPolicy Bypass -File arduino/car_race/tools/send_keys.ps1 -Port COM5 -Plan "W:600;X:450;A:500;Z:450;W:500;A+X:450;A:300;Z:450;Q:600" -GapMs 0
```

- `-GapMs`는 단계 사이 쉬는 시간(ms)이고 기본은 900입니다. `0`이면 쉬지 않아서, 가던 차에 멈춤 글자가 바로 오는 경우를 흉내 냅니다. 마지막 단계의 로그를 보려면 계획 끝에 차가 모르는 글자(`Q:600`)를 붙입니다. 차는 모르는 글자를 무시합니다.
- 앞 20 cm 안에 물건이 있으면 앞으로 가지 않고 `앞이 막힘`이 뜹니다. 시험 공간이 좁으면 이것이 보일 수 있습니다.

- **담당자 코드로 되돌리는 법:** `git fetch origin` 뒤 `git show origin/yunsuk1590/arduino:arduino/car/car.ino`를 새 폴더 `car/car.ino`로 저장해서 올립니다. 또는 `yunsuk1590/arduino` 브랜치에서 `arduino/car/car.ino`를 열어 올립니다. 그 코드는 `F` = 1초 앞으로, `S` = 멈춤이고 초음파가 없습니다. 이 레포에서 그 브랜치는 읽기만 했습니다.
- 이 차 보드를 `car_race`로 두기로 한 것은, 지금 콘텐츠가 협동 레이싱이라 `F`/`S` 코드를 쓸 일이 없어졌기 때문입니다(Claude 판단). 담당자가 시험하려는 차에는 각자 필요한 코드를 올립니다.
