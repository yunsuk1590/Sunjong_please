# arduino — 차 쪽 작업 기록

아두이노 담당 yunsuk1590의 작업 기록입니다. 코드는 `car/car.ino` 하나입니다.

> **지금 상태 (2026-11-11)**: yunsuk1590이 자기 차에 올려 USB 시험을 했고 정상 동작했습니다(아래 「6. 시험 방법과 결과」). 블루투스로는 아직 시험하지 않았고, 「5. 환경」의 보드 설정과 라이브러리 버전은 아직 적지 않았습니다. 코드는 Claude 도움으로 새로 썼습니다.

## 1. 하는 일

HC-06 블루투스 또는 USB 선으로 들어온 글자 하나를 읽어 차를 움직입니다.

| 글자 | 동작 |
|---|---|
| `F` | 정해진 시간(`FORWARD_MS`)만 앞으로 가고 스스로 멈춤 |
| `S` | 바로 멈춤 |
| 그 밖의 글자, `\r`, `\n` | 무시 |

- 켜지면 멈춘 상태로 시작합니다.
- 블루투스와 USB 모두 9600 bps이고, 어느 쪽 글자든 똑같이 처리합니다.
- 받은 글자와 한 동작을 USB 시리얼로 찍습니다(예: `BT: F -> 앞으로`). 시험할 때 시리얼 모니터에서 볼 수 있습니다.

## 2. 고칠 때 볼 곳 (`car/car.ino` 맨 위)

| 상수 | 지금 값 | 뜻 |
|---|---|---|
| `CMD_FORWARD`, `CMD_STOP` | `'F'`, `'S'` | 글자 약속. 약속이 바뀌면 여기만 고칩니다 |
| `DRIVE_SPEED` | 200 | 모터 세기(0~255) |
| `FORWARD_MS` | 1000 | `F` 한 번에 가는 시간(ms) |
| `RESTART_TIMER_ON_REPEAT` | `true` | 가는 도중 `F`가 또 오면 시간을 다시 잴지(`true`) 무시할지(`false`) |
| `LEFT_FORWARD_DIR`, `RIGHT_FORWARD_DIR` | `FORWARD` | 바퀴가 반대로 돌면 그 바퀴만 `BACKWARD`로 바꿉니다 |

## 4. 하드웨어와 배선

키트 자료를 기준으로 코드에 넣은 값입니다. **조립한 차가 실제로 같은지는 아직 확인하지 않았습니다.**

| 항목 | 코드에 넣은 값 | 확인 |
|---|---|---|
| 모터 드라이버 | L293D 모터 쉴드, Adafruit Motor Shield V1(`AFMotor`) | 11/11 차에서 동작 확인(yunsuk1590) |
| 왼쪽 바퀴 / 오른쪽 바퀴 | 쉴드 M1 / M4 | 11/11 두 바퀴가 도는 것 확인. 어느 쪽이 M1인지는 따로 보지 않음 |
| `FORWARD`가 실제로 앞인지 | 두 바퀴 모두 `FORWARD` | 11/11 확인: 앞으로 감(yunsuk1590) |
| HC-06 | SoftwareSerial, 아두이노 RX = A5, TX = A4, 9600 bps | 미확인 |

## 5. 환경

yunsuk1590이 11/11에 차 시험을 한 컴퓨터 기준입니다. 포트가 `COM5`이므로 윈도우 컴퓨터입니다(안내 문서의 맥이 아님).

| 항목 | 값 |
|---|---|
| Arduino IDE 버전 | 2.3.10 |
| 보드 설정 | (업로드에 성공한 보드 이름 적기. 우노 계열은 짐작) |
| 포트 이름 | `COM5` (윈도우. 컴퓨터마다 번호가 다를 수 있음) |
| USB 드라이버를 따로 설치했는지 | 설치한 것 같음(yunsuk1590 기억, 확실하지 않음) |
| 모터 라이브러리 | Adafruit Motor Shield library(V2가 아닌 것), 버전: (적기) |

라이브러리와 드라이버 파일은 레포에 넣지 않습니다. 각자 설치합니다.

## 6. 시험 방법과 결과

1. USB 선으로 연결하고 `car/car.ino`를 업로드합니다.
2. 시리얼 모니터를 9600으로 열면 `car 준비됨`이 보입니다.
3. `F`를 보내면 차가 앞으로 갔다가 약 1초 뒤 스스로 멈춥니다. 가는 도중 `S`를 보내면 바로 멈춥니다.
4. 맥에서 HC-06과 짝을 맺고 `/dev/cu.HC-06…` 포트로 같은 시험을 합니다. 안 되면 넘어가도 됩니다(발표회는 sunbell 윈도우 노트북).

| 시험 | 결과 | 날짜 |
|---|---|---|
| 컴파일 | 오류 없음(프로그램 4,320바이트). sunbell 윈도우 노트북, 보드 「Arduino Uno」 설정. `docs/arduino-brief.md`(sunbell/team)에 적힌 결과 | 11/10 |
| 업로드 | 됨 (yunsuk1590의 차) | 11/11 |

| USB: `S`로 바로 멈추는지 | 정상. 가는 도중에도 바로 멈춤 | 11/11 |
| USB: `F` 한 번에 약 1초 가고 스스로 멈추는지 | 정상. 1초와 세기 200 그대로 둠 | 11/11 |
| 블루투스: 같은 시험 | 아직 안 함(USB만 시험). sunbell 노트북과 이어 볼 때 확인 | |
| 반응이 바로 오는지(느낌) | USB에서 정상 | 11/11 |

## 7. 알아 둘 것 (Claude 분석)

- HC-06은 USB 업로드와 다른 핀(A4, A5)을 쓰므로, 업로드할 때 블루투스 모듈을 뽑지 않아도 됩니다. 조립한 차의 배선이 다르면(HC-06이 0, 1번 핀에 있으면) 이 말은 맞지 않습니다.
- 모르는 글자를 받으면 움직이지 않고 시리얼 모니터에 글자 코드만 찍습니다. 통신 속도가 안 맞아 깨진 글자가 올 때 알아보기 쉽습니다.
