# motion: 몸 동작 인식 확인 프로그램

웹캠 앞에서 움직이면 몸 동작을 알아보고, 화면에 동작 이름·속도·지연을 보여 주는 프로그램입니다.
MediaPipe 담당 sunbell이 만들고 있습니다. 계획은 `docs/plan-motion-recognition.md`, 결정 기록은 `docs/decisions.md`에 있습니다.

**새로 합류해서 개발할 사람은 [`docs/handover.md`](../docs/handover.md)부터 읽어 주세요.** 정확한 환경(파이썬 3.11 등), 지금 하던 일, 남은 일이 정리되어 있습니다.

**지금 단계(11/19): 4단계 완료(11/5), 11/11 학과 발표회 시연 성공. 지금은 이음제(11/28) 「협동 레이싱」용으로 역할별(P1/P2) 글자 보내기를 만들었고, 차 시험을 앞두고 있습니다(6번의 「협동 레이싱」). 5단계(속도 다듬기 + 마무리 확인)는 11/11 뒤로 미뤘습니다.** 몸 뼈대 위에 동작 판정 결과를 보여 주고, 결과가 잠깐 튀어도 바뀌지 않게 하는 떨림 방지를 더했습니다. 판정하는 동작은 이음제용 팔 동작 4개(11/17)입니다: 두 팔 들기(`ARMS_UP`), 왼팔 들기(`LEFT_UP`), 오른팔 들기(`RIGHT_UP`), 팔 양옆으로 벌리기(`T_POSE`). 한 번에 하나만 켜집니다. 몸 좌우 기울이기(`LEAN_LEFT/RIGHT`)는 11/17부터 목록에서 뺐습니다(코드는 남아 있음). 두 팔을 들면 글자 `F`를 보낼 수 있습니다(6번의 「글자 보내기」).

모든 팀원이 **같은 방법**으로 실행합니다: 처음 한 번 `setup`, 그 뒤로는 `run`을 더블클릭하면 됩니다.

> **맥은 아직 시험 안 함.** 지금까지 이 프로그램은 **윈도우(sunbell 노트북)에서만** 돌려 봤습니다.
> 맥에서 `setup.command`, `run.command`, 카메라(`avfoundation`), 글자 보내기(`pyserial`, 블루투스 포트)가 되는지는 **확인된 적이 없습니다**(팀 안건 개발 6).
> 맥에서 처음 돌릴 때는 안 되는 곳이 나올 수 있으니, 안 되면 화면이나 터미널 글을 그대로 sunbell에게 보내 주세요.
> 맥에서 차에 글자를 보낼 때는 명령이 윈도우와 포트 이름만 다릅니다(아래 6번 「협동 레이싱」의 「맥에서」).

## 2. 레포 받기 (처음 한 번)

**ZIP으로 내려받지 말고** git으로 받습니다. ZIP으로 받으면 맥이 `.command` 파일 실행을 막습니다.
터미널(윈도우는 PowerShell)에서 아래 세 줄을 차례로 입력합니다.

```
git clone https://github.com/yunsuk1590/Sunjong_please.git
cd Sunjong_please
git switch sunbell/motion
```

이미 받아 두었다면 `Sunjong_please` 폴더에서 `git pull`만 하면 최신 내용이 됩니다.

## 3. 설치 (처음 한 번)

`Sunjong_please/motion` 폴더를 열고 아래 파일을 더블클릭합니다.

- 윈도우: **`setup.bat`**
- 맥: **`setup.command`**

진행 순서는 다음과 같습니다.
1. 가상환경(이 프로그램 전용 부품 설치 공간) 만들기
2. 부품 설치
3. 모델 파일 받기
4. 설치 확인

처음에는 몇 분 걸릴 수 있습니다.
- `[완료] 준비가 끝났습니다`가 나오면 성공입니다.
- `[중단]`이 나오면 그 화면을 캡처해서 sunbell에게 보내 주세요.
- 여러 번 실행해도 괜찮습니다. 이미 된 단계는 건너뜁니다.

## 4. 실행

- 윈도우: **`run.bat`** 더블클릭
- 맥: **`run.command`** 더블클릭
  - 처음 실행할 때 "터미널이 카메라에 접근하려고 합니다"라는 창이 뜨면 **허용**하세요.
  - 허용한 뒤에도 영상이 안 나오면 프로그램을 끄고 다시 실행하세요.

**끄는 방법**: 창에서 `q` 또는 `Esc`, 창 닫기(X), 터미널에서 Ctrl+C. 끄면 터미널에 요약이 찍힙니다.

## 5. 화면 읽는 법

```
CAMERA 30 fps   LOOP 29 fps   LATENCY 25 ms
INFER 18 ms   MODEL full   PERSON 1
640x480 ? MSMF
ARMS: L wrist UP  R elbow UP
RAW: ARMS_UP
WAIT arms 0.25/0.35s  grace 0.10s  lost 0.5s
OUTPUT no port (fake)  sent 2  dropped 0  last F 1.6s ago
q: quit
```

- 몸 위에는 회색 뼈대 선과 주황색 관절 점이 그려집니다. 잘 안 보이는 관절(가려진 팔 등)은 그리지 않습니다.
- **화면 아래 큰 글씨**: 떨림을 막은 뒤의 결과(STABLE)입니다. 팔 동작은 한 번에 하나만 켜집니다(`ARMS_UP`, `LEFT_UP`, `RIGHT_UP`, `T_POSE`). 아무 동작도 없거나 사람이 없으면 회색 `NONE`이 나옵니다.
- **`RAW:` 줄**: 떨림을 막기 전의 원래 결과입니다. 사진 한 장마다 바로 바뀝니다.
- **큰 글씨 위의 색 띠**: 최근 3초 동안 동작마다 RAW(위)와 STABLE(아래)이 켜져 있던 때를 색으로 보여 줍니다. 오른쪽 끝이 지금입니다.
  - 색: 초록 = ARMS_UP, 파랑 = LEFT_UP, 주황 = RIGHT_UP, 보라 = T_POSE, 어두운 회색 = 동작 없음(기울이기를 다시 켜면 LEAN_LEFT는 파랑, LEAN_RIGHT는 주황)
  - RAW 띠가 끊겨도 STABLE 띠가 이어져 있으면 떨림 방지가 제대로 동작한 것입니다.
- **`WAIT` 줄**: 떨림 방지 대기 시간(초)입니다. `arms 0.25/0.35s`는 팔 동작이 0.25초 유지돼야 켜지고 0.35초 사라져야 꺼진다는 뜻입니다. `grace`는 기다리는 동안 결과가 이 시간보다 짧게 끊기면 기다린 시간을 이어 간다는 뜻입니다(0.1초, 0이면 끊길 때마다 처음부터 다시 셈). `lost`는 사람이 이 시간 넘게 안 보이면 모든 동작을 끈다는 뜻입니다.
  - 기다리는 시간만큼 반응이 늦어집니다(안정성과 빠르기는 맞바꾸는 관계).
- **`OUTPUT` 줄**: 글자 보내기 상태입니다. 6번의 「글자 보내기」를 봅니다.
- **맨 아래 막대**: 어깨 기울기입니다. 기울이기를 목록에서 뺀 지금(11/17부터)은 나오지 않고, `gestures/__init__.py`에서 한 줄 주석을 풀면 다시 나옵니다. `ARMS:` 줄에는 팔마다 `UP`(들림) / `OUT`(옆) / `DOWN`(내림) / `MID`(중간)이 나옵니다.
  - 가운데 흰 선이 0도입니다.
  - 노란 선은 켜짐 기준, 회색 선은 꺼짐 기준입니다.
  - 체험자가 왼쪽으로 기울면 점이 왼쪽으로 갑니다(거울 화면 기준). LEAN이 켜지면 점이 초록색이 됩니다.

**동작 판정 기준**(어떤 동작을 무엇을 보고 몇 도·어느 높이로 판정하는지)은 [`docs/gesture-rules.md`](../docs/gesture-rules.md)에 모아 두었습니다.
- `ARMS:` 줄: 각 팔을 손목(wrist)·팔꿈치(elbow) 중 무엇으로 판정했는지(`L`은 화면 왼쪽 팔)
- `LEAN:` 줄: 어깨 기울기(판정에 씀)와 몸통 기울기(`torso`, 비교용)

| 표시 | 뜻 | 좋은 값 |
|---|---|---|
| CAMERA | 카메라에서 1초에 받은 사진 수 | 25 이상 |
| LOOP | 프로그램이 1초에 처리해서 보여 준 사진 수 | CAMERA와 비슷 |
| LATENCY | 처리 지연(ms, 1000분의 1초). 사진을 받은 순간부터 화면에 보여 주기 직전까지 걸린 시간. 카메라·모니터 자체의 지연은 빠져 있음 | 작을수록 좋음. 시작 목표는 100 이하 |
| INFER | LATENCY 중 MediaPipe가 몸을 찾는 데 걸린 시간(ms) | 작을수록 좋음 |
| MODEL | 몸 인식 모델. lite = 가벼움, full = 보통 | |
| PERSON / NO PERSON | 찾은 사람 수 / 아무도 없음 | |
| 셋째 줄 | 카메라가 실제로 준 해상도, 영상 형식(모르면 `?`), 카메라 여는 방식 | |

시작할 때 터미널에 `INFO: Created TensorFlow Lite…`, `W0000 …` 같은 영어 줄이 몇 개 나옵니다. MediaPipe가 내는 정상적인 안내라 무시해도 됩니다.

방이 어두우면 카메라가 스스로 노출을 늘리면서 CAMERA 숫자가 떨어질 수 있습니다. 밝은 곳에서 확인하세요.

끌 때 찍히는 요약의 뜻은 다음과 같습니다.
- "보통": 중간값
- "느린 쪽 5%": 가끔 느려질 때의 값

## 6. 설정을 바꿔서 실행 (선택)

더블클릭 대신 터미널에서 실행하면 설정을 붙일 수 있습니다.

- 윈도우(PowerShell, `motion` 폴더에서): `.\run.bat --backend dshow`
- 맥(터미널, `motion` 폴더에서): `./run.command --res 320x240`

| 설정 | 뜻 | 기본값 |
|---|---|---|
| `--camera 1` | 카메라 번호(여러 대일 때) | 0 |
| `--res 320x240` | 요청할 해상도. 카메라가 지원하지 않으면 다른 값이 나옴 | 640x480 |
| `--backend msmf` / `dshow` / `avfoundation` | 카메라 여는 방식 | 윈도우 msmf(안 열리면 dshow), 맥 avfoundation |
| `--no-mirror` | 좌우 반전하지 않기 | 반전함 |
| `--model lite` | 몸 인식 모델(`full` 보통 / `lite` 가벼움. lite는 빠르지만 가만히 있어도 점이 떨림) | full |
| `--num-poses 4` | 한 번에 찾을 최대 사람 수. 1보다 크면 MediaPipe의 떨림 줄이기가 꺼짐 | 1 |
| `--lean-enter 25` | 기울이기가 켜지는 어깨 각도(도) | 22 |
| `--arms-on 0.15` / `--arms-off 0.25` | 떨림 방지: 팔 동작 4개가 켜지려면 유지, 꺼지려면 사라져야 하는 시간(초). 11/5 확정 | 0.25 / 0.35 |
| `--up-angle 40` / `--up-keep-angle 25` | 팔 들림: 어깨→손목 선이 수평에서 위로 이만큼(도) 이상이어야 켜짐 / 이미 켜진 뒤 유지하는 각도. 일부러 든 팔이 안 켜지면 낮추고, 비스듬한 팔이 켜지면 올림. 11/17 시작값 | 50 / 30 |
| `--grace 0` | 떨림 방지: 기다리는 동안 이 시간(초)보다 짧은 끊김은 봐줌. 0이면 끊길 때마다 처음부터 다시 셈. 11/17 | 0.1 |
| `--compare-grace` | 시험용: 같은 결과를 끊김 봐주기 끔으로도 걸러서, 끝날 때 바뀐 횟수를 나란히 보여 줌. 화면과 글자 보내기에는 영향 없음 | 꺼짐 |
| `--lean-on 0.1` / `--lean-off 0.15` | 떨림 방지: 기울이기의 같은 시간(초). 11/5 확정 | 0.20 / 0.25 |
| `--lost 1.0` | 사람이 이 시간(초) 넘게 안 보이면 모든 동작을 끔. 더 짧게 안 보이면 결과를 유지 | 0.5 |
| `--lean-exit 10` | 기울이기가 꺼지는 어깨 각도(도). 켜짐 각도보다 작게 | 7 |
| `--port COM5` | 글자를 보낼 포트. 적지 않으면 보내지 않고 화면과 터미널에만 표시 | 없음 |
| `--baud 9600` | 통신 속도 | 9600 |
| `--send-on LEFT_UP` | 이 동작이 켜지는 순간 글자를 보냄(`ARMS_UP` / `LEFT_UP` / `RIGHT_UP` / `T_POSE`. 기울이기를 다시 켜면 `LEAN_LEFT` / `LEAN_RIGHT`도) | ARMS_UP |
| `--letter-on F` | 동작이 켜지는 순간 보낼 글자 | F |
| `--letter-off Q` | 동작이 꺼지는 순간 모든 동작에 보낼 글자. 빈칸(`--letter-off ""`)이면 일부러 보내지 않음. **안 적으면** `W A S D`는 축마다 멈춤 글자(앞뒤 `X`, 좌우 `Z`, 11/20), 11/11 방식은 보내지 않음 | 안 적음 |
| `--stop-repeats 3` | 팔을 내릴 때 멈춤 글자(`X`/`Z`)를 연달아 보내는 횟수(처음은 바로, 나머지는 `--repeat-seconds` 간격). 글자 하나를 잃어도 서게 함 | 3 |
| `--letter-quit XZ` | 프로그램을 끌 때 보낼 글자. 빈칸이면 보내지 않음. 안 적으면 11/11 방식은 `S`, 차와 연결된 노트북은 `XZ`(앞뒤·좌우 둘 다 끔), `--send-to`로 보내기만 하는 노트북은 자기 축(P2 `Z`) | S / XZ / Z |
| `--role P1` | 협동 레이싱 역할(11/19). P1 = 두 팔 들기 W(앞), T자 S(뒤) / P2 = 왼팔 A(왼쪽), 오른팔 D(오른쪽). 적으면 켜져 있는 동안 반복해서 보냄 | 없음 |
| `--letters ARMS_UP=W,T_POSE=S` | 동작별 글자를 직접 정함. 적으면 역할의 글자 표 대신 씀 | 없음 |
| `--send-mode once` / `repeat` | once = 켜지는 순간 한 번(리듬게임용, 11/11 방식) / repeat = 켜져 있는 동안 반복(컨트롤러식). 안 적으면 역할이나 글자 표가 있을 때 repeat | once |
| `--repeat-seconds 0.15` | repeat일 때 같은 글자를 다시 보내는 간격(초). 시작값 | 0.15 |

### 글자 보내기 (11/11 학과 발표회 시연용)

두 팔 들기가 켜지는 순간 `F`를 한 번 보내고, 프로그램을 끌 때 `S`를 한 번 보냅니다.
다시 보내려면 팔을 내렸다가 다시 듭니다. 아래 두 경우에는 팔을 내리지 않아도 `F`가 나갑니다.
- 프로그램을 켤 때 이미 팔을 들고 있었을 때
- 팔을 든 채로 사람을 0.5초 넘게 놓쳤다가 다시 잡았을 때

**더블클릭으로 실행하면 글자를 보내지 않습니다.** 화면과 터미널에만 표시합니다. 실제로 보내려면 터미널에서 포트를 적습니다.

- 윈도우(PowerShell, `motion` 폴더에서): `.\run.bat --port COM5`
- 포트 번호는 윈도우 블루투스 설정의 COM 포트 목록에서 **나가는(Outgoing)** 포트를 찾습니다. USB 선으로 바꿀 때는 번호만 바꿉니다.
- `git pull`로 이 기능을 처음 받았다면 `setup`을 한 번 다시 실행합니다(`pyserial` 설치). 설치하지 않아도 프로그램은 켜지지만 글자를 보내지 못합니다.

`OUTPUT` 줄의 뜻은 다음과 같습니다.

| 표시 | 뜻 |
|---|---|
| `no port (fake)` | 포트를 적지 않음. 보내지 않고 표시만 함 |
| `no pyserial (fake)` | `pyserial`이 없음. `setup`을 다시 실행 |
| `COM5 connecting...` | 포트를 여는 중. 블루투스는 몇 초 걸릴 수 있음 |
| `COM5 OPEN` | 포트가 열림. **글자가 차까지 도착했다는 뜻은 아님** |
| `COM5 ERROR - retrying` | 열지 못했거나 끊김. 3초마다 다시 시도함. 프로그램은 꺼지지 않음 |
| `sent` / `dropped` | 보낸 글자 수 / 포트가 열려 있지 않아서 버린 글자 수 |
| `last F 1.6s ago` | 마지막 글자와 지난 시간. 버린 글자면 `last F dropped` |

포트가 열려 있지 않을 때 나온 글자는 **쌓아 두지 않고 버립니다.** 쌓아 두면 연결되는 순간 아무도 팔을 들지 않았는데 차가 출발할 수 있기 때문입니다.

### 협동 레이싱: 역할별 컨트롤러식 보내기 (11/19)

노트북 한 대에 사람 한 명이 한 역할을 맡습니다. 실행할 때 역할을 고릅니다.

```
.\run.bat --port COM11 --role P1
.\run.bat --port COM11 --role P2
```

| 역할 | 동작 | 보내는 글자 |
|---|---|---|
| P1 | 두 팔 들기 (`ARMS_UP`) | `W` (앞) |
| P1 | 팔 양옆으로 벌리기 (`T_POSE`) | `S` (뒤) |
| P2 | 왼팔 들기 (`LEFT_UP`) | `A` (왼쪽) |
| P2 | 오른팔 들기 (`RIGHT_UP`) | `D` (오른쪽) |

- 동작이 **켜져 있는 동안** 같은 글자를 0.15초마다 다시 보냅니다. 팔을 내리면 보내지 않고, 차는 약 0.3초 글자가 없으면 그 입력을 끕니다(아두이노 세션 설계). 그래서 팔을 내린 뒤 차가 서기까지는 「떨림 방지 꺼짐 대기 0.35초 + 차의 0.3초」쯤 걸립니다(Claude 계산, 시험으로 재 볼 것).
- 자기 역할이 아닌 동작은 글자를 보내지 않습니다. 예: P1이 왼팔을 들어도 아무것도 안 갑니다.
- **멈춤 글자는 축마다 따로입니다(11/20 sunbell 결정): `X` = 앞뒤만 끔, `Z` = 좌우만 끔.** 팔을 내리면 그 축의 멈춤 글자를 보냅니다. P1(`W`/`S`)은 `X`, P2(`A`/`D`)는 `Z`이고, 한 사람이 멈춰도 다른 사람의 입력은 안 끊깁니다. 차가 시간 제한(약 0.3초)을 기다리지 않고 바로 서서, 서기까지의 시간은 노트북 꺼짐 대기(`--arms-off`)가 대부분입니다.
  - 멈춤 글자는 **3번 연달아** 보냅니다(`--stop-repeats`). 글자 하나를 잃어도 서게 하려는 것(아두이노 세션 제안)입니다. 그 사이에 같은 축을 다시 켜면 남은 멈춤 글자는 보내지 않아서 새로 켠 입력이 멈추지 않습니다.
  - 같은 축 안에서 바로 바꿀 때(`W`에서 `S`)는 멈춤 글자를 보내지 않고, 다른 축으로 바로 바꿀 때(`W`에서 `A`, 노트북 1대에서 네 동작을 쓸 때)는 앞 축의 멈춤 글자와 새 글자를 함께 보냅니다.
  - **차 코드가 `X`/`Z`를 나눠 받기 전에는 차에서 `Z`가 무시될 수 있습니다.** 그래도 차가 0.3초 뒤에 스스로 끄므로 위험하지는 않습니다. 차 시험은 아두이노 쪽이 올린 뒤에 합니다.
- **끌 때는 `X`와 `Z`를 이어서 보냅니다(11/20 sunbell 결정: 「X와 Z를 이어서」).** 차와 연결된 노트북(P1)은 `XZ`로 앞뒤·좌우를 모두 끕니다. 이 노트북이 꺼지면 P2의 글자도 더는 안 넘어가기 때문입니다. `--send-to`로 보내기만 하는 노트북(P2)은 자기 축의 `Z`만 보냅니다(Claude 제안, sunbell 확인 전. P1의 앞뒤 입력은 안 끊김). 11/11 방식의 `S`는 협동 레이싱에서 「뒤로」라서 역할을 고르면 보내지 않습니다.
- 글자는 대문자 `W` `A` `S` `D`로 보냅니다(시작값). 차 코드가 소문자를 쓰면 `--letters ARMS_UP=w,T_POSE=s`처럼 바꿉니다.
- **노트북 1대로 시험하기** (차 시험용. 차에는 블루투스 모듈이 1개라 포트도 1개이고, 한 포트는 프로그램 하나만 쓸 수 있습니다)
  - 한 사람이 네 동작을 모두 하면서 네 글자를 모두 보내려면:
    ```
    .\run.bat --port COM11 --letters ARMS_UP=W,T_POSE=S,LEFT_UP=A,RIGHT_UP=D
    ```
  - 역할만 번갈아 시험하려면 프로그램을 끄고(`q`) `--role P1`, `--role P2`로 따로 실행합니다.
  - `COM11`은 이 노트북에서 차의 블루투스에 잡힌 번호입니다. 다른 노트북에서는 번호가 다릅니다. 윈도우 「장치 관리자」의 「포트」나 `[System.IO.Ports.SerialPort]::GetPortNames()`로 찾고, HC-06은 짝을 맺은 뒤 「나가는(Outgoing)」 포트를 씁니다.
  - **한계**: 동작이 한 번에 하나만 켜지므로 `W`와 `A`를 **동시에** 보내 보는 시험(앞으로 가면서 왼쪽으로 틀기)은 노트북 1대로 안 됩니다. 그 시험은 노트북 2대 합치기가 되어야 하거나, 아두이노 시리얼 모니터에서 글자를 직접 보내서 합니다.
  - 차 없이 화면만 보려면 `--port`를 빼고 실행합니다(터미널에 `[가짜 보내기]`로 표시).
  - **맥에서** (**아직 시험 안 함**): 터미널에서 `motion` 폴더로 가서 `./run.command`에 같은 설정을 붙입니다. 포트 이름만 다릅니다. 짐작이지만 HC-06과 짝을 맺으면 `/dev/cu.`로 시작하는 이름이 생기니 `ls /dev/cu.*`로 찾습니다.
    ```
    ./run.command --port /dev/cu.여기에찾은이름 --letters ARMS_UP=W,T_POSE=S,LEFT_UP=A,RIGHT_UP=D
    ```
- **노트북 2대 길 확인** (11/19 sunbell 결정: 같은 와이파이에서 UDP로 하고 학교 와이파이로 먼저 시험)
  - 차에 블루투스 모듈이 1개라서 P2의 글자를 P1 노트북이 받아 차로 넘겨야 합니다. **프로그램에 붙이는 것은 아직 만들지 않았고**, 먼저 `net_check.py`로 두 노트북 사이의 길이 열려 있는지만 봅니다. 차, 블루투스, 몸 인식은 쓰지 않습니다.
  - 두 노트북을 **같은 와이파이**에 연결하고 `motion` 폴더에서 실행합니다.
    ```
    # P1 노트북(받는 쪽): 화면에 「이 노트북의 주소」가 나옵니다
    .\.venv\Scripts\python.exe net_check.py listen

    # P2 노트북(보내는 쪽): 위에서 나온 P1의 주소를 적습니다(예: 192.168.0.12)
    .\.venv\Scripts\python.exe net_check.py send 192.168.0.12
    ```
  - P1에서 처음 켤 때 윈도우가 「네트워크 접근을 허용할까요?」라고 물으면 **허용**합니다. 학교 와이파이가 「공용 네트워크」로 잡히면 「공용 네트워크」에도 체크해야 할 수 있습니다(Claude 짐작).
  - 결과: P2 화면에 「글자 N번 보냄, 답 M번 받음」과 왕복 시간이 나옵니다. **N = M이면 길이 열려 있습니다.** 답이 0이면 막힌 것이니 화면의 확인 목록(listen 켜짐, 주소, 같은 와이파이, 방화벽, 기기 간 통신 차단)을 봅니다. P1은 Ctrl+C로 끄면 「0.3초 넘게 끊긴 횟수」가 나오는데, 차는 0.3초 넘게 글자가 없으면 그 입력을 끄므로 0에 가까워야 합니다.
  - 맥에서는 `.venv/bin/python net_check.py ...` 또는 `python3 net_check.py ...`입니다. 자동 시험은 `test_net_check`이고 같은 노트북 안에서 돌아갑니다.
  - **시험 결과(11/19, 학교 와이파이, 윈도우 P1 + 맥 P2)**: 67번 보내 67번 답이 왔고, 왕복 시간은 평균 16 ms, 가장 긴 것 138 ms였습니다. 같은 와이파이의 두 노트북은 서로 `ping`도 됐습니다. 학교 와이파이가 기기끼리의 통신을 막고 있지 않았습니다.
- **노트북 2대로 하기** (11/19, 프로그램에 붙임)
  - **P1 노트북**(차와 블루투스로 연결된 노트북)은 P2가 보낸 글자를 받아 자기 글자와 함께 차로 넘깁니다. `--listen`을 붙입니다.
    ```
    .\run.bat --port COM11 --role P1 --listen --allow-from P2주소
    ```
  - **P2 노트북**은 차 포트 대신 P1의 주소로 보냅니다. `--send-to`를 붙입니다. 주소는 P1에서 `ipconfig`(맥은 `ipconfig getifaddr en0`)로 알아냅니다.
    ```
    .\run.bat --role P2 --send-to P1주소
    ```
    맥에서는 `./run.command --role P2 --send-to P1주소`입니다(**맥에서 이 프로그램 전체는 아직 시험 안 함**. `net_check.py`만 맥에서 시험했습니다).
  - 화면에서 확인하는 곳
    - P2: `OUTPUT UDP 주소:5005 OK 16ms`. `OK`는 P1이 답을 보냈다는 뜻이고 숫자는 왕복 시간입니다. 답이 없으면 `NO REPLY`입니다. 팔을 안 들고 있어도 1초마다 「살아 있음」 신호(`H`)를 보내서 연결 상태가 보입니다.
    - P1: `NET :5005 recv 52  last A 0.1s ago  hb 0.4s`. P2에서 받은 글자 수, 마지막으로 받은 글자, 마지막 「살아 있음」 신호가 온 뒤 지난 시간입니다.
  - 규칙
    - P1은 P2의 `W A S D`(가고 서기)와 `X` `Z`(멈춤)를 차로 넘깁니다. 살아 있음 신호(`H`)는 넘기지 않고, 그 밖의 글자는 버립니다. P2의 `Z`는 좌우만 끄므로 P1의 앞뒤 입력을 끊지 않습니다(11/20). P2가 끊겨도 차가 0.3초 뒤에 그 입력을 스스로 끕니다.
    - P1의 포트는 글자 종류마다 하나씩만 남깁니다. P1의 `W`와 P2의 `A`가 거의 동시에 와도 서로 지우지 않습니다(자동 시험).
    - **`--allow-from`을 적지 않으면 같은 와이파이의 아무 기기가 보낸 글자나 받아서 차로 넘깁니다.** 학교 와이파이에서는 P2 노트북의 주소를 적는 것이 안전합니다. 주소가 바뀔 수 있어서(와이파이가 새로 주는 번호) 시연 직전에 다시 확인합니다.
    - `--port`와 `--send-to`, `--send-to`와 `--listen`은 같이 쓸 수 없습니다. 한 노트북은 한 역할입니다.
    - 윈도우에서 P1을 처음 켜면 「네트워크 접근을 허용할까요?」가 뜹니다. **허용**합니다.
  - 차 없이 길만 시험하려면 P1에서 `--port` 없이 `.\run.bat --role P1 --listen`을 켭니다. P2에서 받은 글자가 터미널에 `[가짜 보내기]`로 보입니다.
- 맵은 「서킷 + S자 구간」입니다(11/19 sunbell 결정). 그래서 P2가 왼팔과 오른팔을 둘 다 번갈아 씁니다.
- 11/11 방식(켜지는 순간 한 번)도 그대로 있습니다. 역할 없이 실행하거나, 역할과 함께 `--send-mode once`를 적습니다. 리듬게임용으로 남겨 둔 것입니다.
- 터미널에는 같은 글자를 반복해서 보내는 동안 한 줄만 나옵니다. 끌 때 「글자 하나를 포트에 쓰는 데 가장 오래 걸린 시간」이 나와서 블루투스가 느린지 볼 수 있습니다.
- 글자는 쌓아 두지 않습니다. 포트가 막혀 있는 동안 온 글자는 가장 최근 하나만 남깁니다(자동 시험으로 확인). 9600 bps는 1초에 약 960글자를 보낼 수 있는데 0.15초마다 한 글자는 1초에 약 7글자라 여유가 큽니다(Claude 계산).

**자동 시험**(카메라와 차가 없어도 됩니다, `motion` 폴더에서):
- 윈도우: `.venv\Scripts\python.exe -m unittest test_output test_gestures`
- 맥: `.venv/bin/python -m unittest test_output test_gestures`
- `test_gestures`는 팔 동작 4개 판정과 끊김 봐주기를 가짜 관절 위치로 시험합니다(11/17).

## 8. 파일 설명

| 파일 | 하는 일 |
|---|---|
| `setup.bat` / `setup.command` | 처음 한 번 더블클릭. 파이썬 3.11을 찾아 `setup_env.py`를 실행 |
| `run.bat` / `run.command` | 더블클릭하면 `run.py`를 실행 |
| `setup_env.py` | 가상환경 만들기 → 부품 설치 → 모델 받기 → 설치 확인(윈도우·맥 공통) |
| `run.py` | 실행 파일. 카메라 사진 받기 → 몸 찾기 → 그리기 → 화면에 보여 주기 순서를 정함 |
| `config.py` | 설정값 모음(카메라 번호, 해상도, 카메라 여는 방식, 모델, 사람 수) |
| `pose.py` | MediaPipe로 몸 관절 33개 점을 찾음. 결과는 "사람 목록" |
| `stabilizer.py` | 떨림 방지. 결과가 일정 시간 이어져야 바뀌게 하고, 사람이 오래 안 보이면 모든 동작을 끔 |
| `gestures/` | 동작 규칙 모음. 동작 하나 = 파일 하나(`arms_up.py`는 팔 동작 4개, `lean.py`는 기울이기로 지금은 목록에서 뺌). `base.py`는 공통 틀, `__init__.py`는 동작 목록 |
| `camera.py` | 카메라 담당. 따로 도는 작업 줄이 가장 최근 사진 1장만 들고 있어 지연이 쌓이지 않음 |
| `metrics.py` | 초당 장수와 지연을 재는 도우미 |
| `overlay.py` | 화면 위에 글씨와 몸 뼈대를 그림 |
| `output.py` | 글자 보내기. 동작이 켜지는 순간을 찾아 글자 하나를 COM 포트로 보냄 |
| `test_output.py` | 글자 보내기 자동 시험 |
| `test_gestures.py` | 팔 동작 4개 판정과 짧은 끊김 봐주기 자동 시험 |
| `download_models.py` | 구글 공식 저장소에서 몸 인식 모델을 받음(버전 고정, 크기 확인) |
| `requirements.txt` | 설치할 부품 목록(정확한 버전으로 고정) |

**설치 목록에 대한 메모.** `requirements.txt`에는 한글을 쓰지 않습니다. 한국어 윈도우의 설치 도구가 한글을 읽다가 멈추기 때문입니다. 버전을 고른 이유는 여기에 적습니다.
- **MediaPipe 1.0.0**: 최신 1.0.1은 맥에서 몸 인식을 시작하자마자 강제 종료됩니다(공식 이슈 #6356). 고친 버전이 나오면 다시 검토합니다.
- **OpenCV**: `opencv-contrib-python`만 씁니다. `opencv-python`을 같이 설치하면 충돌합니다.
- **pyserial 3.5**: 파이썬에서 COM 포트를 쓰는 부품입니다(11/8 기준 최신).

## 9. 새 동작 추가하는 방법

동작 하나는 `gestures` 폴더 안의 파일 하나입니다.

1. `gestures/arms_up.py`를 복사해 새 파일을 만듭니다(예: `squat.py`).
2. 새 파일에서 세 가지를 새 동작에 맞게 고칩니다.
   - `name`: 동작 이름
   - `states`: 나올 수 있는 상태 이름들
   - `check()`: 판정 규칙
3. `gestures/__init__.py`의 `make_gestures()` 목록에 한 줄을 추가합니다.
   - 떨림 방지 시간을 따로 정하려면 `stabilizer.py`의 `make_stabilizer()`에도 한 줄을 추가합니다. 안 하면 기본값(켜짐 0.15초, 꺼짐 0.2초)을 씁니다.
4. 판정 기준을 [`docs/gesture-rules.md`](../docs/gesture-rules.md)에 같은 형식으로 적습니다.

규칙을 쓸 때 알아 둘 것
- 관절 위치는 `frame.point(PoseLandmark.NOSE)`처럼 꺼냅니다. 결과는 픽셀 좌표이고, y는 아래로 갈수록 커집니다.
- 왼쪽·오른쪽은 화면에 보이는 쪽(`frame.shoulders()`가 화면 왼쪽부터 돌려줌)으로 정합니다. MediaPipe의 LEFT/RIGHT 이름은 거울 화면에서 뒤바뀌기 때문입니다.
- `history`에는 최근 약 2초의 사진 정보가 들어 있습니다. 제자리 달리기처럼 반복되는 동작은 이것으로 판정합니다.
- `previous`는 이 동작의 직전 상태입니다. 켜질 때와 꺼질 때 기준을 다르게 둘 때 씁니다.
